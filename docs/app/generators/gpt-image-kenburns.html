方式設計書: gpt-image-kenburns

Fix（14-12 で作成） 方式名（レジストリキー）: gpt-image-kenburns 最終更新: 2026-07-26
本書の位置づけ 生成方式 gpt-image-kenburns の方式固有仕様（使用 API・合成仕様・ffmpeg エンコード・選曲）を記録する。全方式共通の契約（方式インターフェース）と方式カタログは batch-flow.html セクション 2.1、分冊ルール（1 方式 1 本・本採用時に作成）は design-outline.html セクション 1.1 を参照。本書は実装（services/image-batch/app/generators/gpt_image_kenburns.py）を正として記述している。

1. 方式概要

縦長の静止画を OpenAI Images API で 1 枚生成し、ぼかし背景付きの 9:16 キャンバスに合成したうえで、ffmpeg のゆっくりしたズーム（Ken Burns 効果）と登録済み音源を重ねて 10 秒の MP4（リール）を生成する簡易動画方式。生成 AI 動画 API を使わないため生成コストは静止画 1 枚分に収まる（Phase 14-2 の壁打ちで採用した初期スコープ）。Phase 14-7 で実装し、14-10 でセット fantasy-animals-1 が採用、14-12 で定常運用に入った（= 本採用）。

2. 契約の実装

共通の契約（batch-flow.html「生成方式の契約」。Phase 14-4 で「最終メディアを返す」に一般化）を次のシグネチャで実装する。

generate(context: GeneratorContext) -> GeneratorResult

本方式は契約のうち以下を使う。冪等性（完了判定）・S3 保存・DB 登録・トランザクション制御は共通骨格（processing.py）の責務であり、本方式は関与しない。

要素使い方
context.prompt_configプロンプト・API パラメータ・set_id（選曲のキー）
context.cursoraudio_assets の選曲 SELECT と last_used_at の UPDATE
context.s3_client / context.s3_bucket音源ファイルの取得（acps_shared.s3.get_object）
戻り値 GeneratorResult.mediaMediaOutput 1 件（content=MP4、file_format='mp4'、width / height / duration_seconds / audio_asset_id）
戻り値 GeneratorResult.intermediatesIntermediateOutput 1 件（生成静止画 JPEG、suffix='_source'、output_index=0）

処理順序: ① API キー取得 → ② Images API で PNG 生成 → ③ JPEG 変換 → ④ 選曲（audio_assets）→ ⑤ 音源を S3 から取得 → ⑥ キャンバス合成（Pillow）→ ⑦ ffmpeg でエンコード → ⑧ last_used_at 更新 → ⑨ GeneratorResult を返す。

3. 入力

入力は PromptConfig（data-model.html）と、set_id に紐づく audio_assets の行。prompt_text / parameters の使い方は gpt-image-single と同一で、OpenAI 呼び出しは共通ヘルパ generators/openai_image.py（load_api_key / build_client / request_images / convert_png_to_jpeg）に集約している。negative_prompt は本方式でも未使用。

キー（parameters）渡し先fantasy-animals-1 の実値
modelimages.generate(model=...)gpt-image-2
sizeimages.generate(size=...)1024x1536（縦長。9:16 キャンバスへの拡大率を抑えるため）
qualityimages.generate(quality=...)high
nimages.generate(n=...)1
複数枚返却時は先頭のみ使用 n が 2 以上で複数枚返った場合、本方式は WARNING ログを出して先頭 1 枚のみを動画化する（1 実行 1 本の運用前提）。0 枚の場合は RuntimeError を送出する。パラメータのバリデーションを行わない点は gpt-image-single と同じ（フェイルラウド）。

4. 認証情報（API キー）

環境変数 API_SECRET_ARN から acps_shared.get_secret_string 経由で取得する（gpt-image-single セクション 4 と同一。「Secret は方式モジュールが自分で取得する」決定を踏襲し、実処理は openai_image.load_api_key() に共通化）。

5. 選曲（audio_assets）

動画には音源が必須のため、方式内で audio_assets から 1 曲を選ぶ。

SELECT id, s3_key FROM audio_assets
 WHERE set_id = %s AND is_active = 1
 ORDER BY last_used_at ASC, id ASC LIMIT 1
  • 順繰り選曲: 最も長く使っていない曲を選ぶ。未使用（last_used_at IS NULL）が最優先（MySQL の ASC で NULL が先頭）、同着は id 昇順
  • 使用マーク: 動画のエンコード成功後に last_used_at を現在 UTC で UPDATE する。コミットは共通骨格が行うため、後続の S3 保存・DB 登録が失敗すればロールバックされ、選曲の副作用は残らない
  • 0 件はフェイルラウド: 有効な音源が 1 件もなければ RuntimeError を送出する（無音動画を作らない。14-4 の決定）

音源の前処理レシピ（切り出し 10 秒・2 パスラウドネス正規化・フェード・AAC 化）と登録手順、ライセンス証跡の管理は operation.html を参照。音源は前処理済み AACである前提で、本方式は再エンコードせず -c:a copy でそのまま多重化する。

6. キャンバス合成（Pillow）

生成画像（縦長だが 9:16 ではない）を 1080x1920 に載せる工程。ズーム終端でも元画像の 100% が可視であることを構造的に保証する。

定数（実装）値意味
OUTPUT_WIDTH / OUTPUT_HEIGHT1080 / 1920出力寸法（9:16）
ZOOM_END1.08ズーム終端倍率
SAFE_BOX_MARGIN8zoompan の整数丸め吸収
BACKGROUND_BLUR_RADIUS48背景のガウシアンぼかし半径（1080x1920 換算）
BACKGROUND_BLUR_DOWNSCALE4ぼかしを 1/4 縮小画像に掛けて拡大（処理時間短縮）
BACKGROUND_BRIGHTNESS0.72背景の減光率（前景とのコントラスト確保）
CANVAS_JPEG_QUALITY90合成キャンバスの JPEG 品質

合成手順:

  1. セーフボックスの導出: (int(1080 / ZOOM_END) - 8, int(1920 / ZOOM_END) - 8) = 992 x 1769。ズームで中央に寄っても常に画面内に残る領域
  2. 前景: ImageOps.contain でセーフボックスにフィット（切らずに全体を収める）。1024x1536 の入力なら 992x1488 になる
  3. 背景: 同じ画像を ImageOps.fit で 1080x1920 に埋め（ここは切れてよい）、1/4 に縮小 → ガウシアンぼかし → 1080x1920 に再拡大 → 明度 0.72 に減光
  4. 合成: 背景の中央に前景を貼り付け、JPEG（品質 90）として返す
決定（Phase 14-11）: 中央クロップを廃止しフィット + ぼかし背景に変更 14-10 の実投稿で画像内の文字が左右で見切れていることが判明した。原因は ffmpeg 側の scale=-2:1920,crop=1080:1920（中央クロップで幅の 15.6% 喪失）と zoompan 1.0→1.08（終盤にさらに各 3.7%）の2 段階クロップで、最終フレームには元画像の横幅の 78% しか映っていなかった。 対策として ffmpeg の中央クロップを廃止し、Pillow の _compose_canvas で「セーフボックスに contain した前景 + ぼかし減光した同一画像の背景」を組んでから zoompan に渡す方式へ変更した。セーフボックスを 出力寸法 / ZOOM_END - マージン として定数から導出しているため、ズーム倍率を変えてもクロップが再発しない。合わせてプロンプト側にも Instagram UI のセーフエリア（右端 12%・下端 15%）を明記した（sets/fantasy-animals-1.html）。

7. ffmpeg エンコード

合成済み JPEG 1 枚と前処理済み AAC を一時ディレクトリに書き出し、ffmpeg を subprocess.run で 1 回呼ぶ。

項目値（実装定数）
入力-loop 1 -framerate 30 -t 10 の静止画 + 音源ファイル
映像フィルタscale=2160:3840（SUPERSAMPLE_FACTOR=2 でスーパーサンプリング）→ zoompan（z=1.0+0.08*on/299・中央固定・d=1・s=1080x1920・fps=30）→ format=yuv420p
映像コーデックlibx264 / -crf 20 / -preset medium / +faststart
音声コーデック-c:a copy（前処理済み AAC をそのまま多重化）
尺-shortest -t 10（10 秒）
タイムアウトFFMPEG_TIMEOUT_SECONDS = 600
スーパーサンプリングの理由 zoompan はズーム倍率を整数ピクセルに丸めるため、等倍のまま掛けると拡大中にカクつき（ジッタ）が出る。出力の 2 倍解像度へ拡大してから s=1080x1920 で縮小することで、丸め粒度が実質半分になり滑らかなズームになる。

ffmpeg が非ゼロ終了・タイムアウト・空ファイル出力のいずれかになった場合は、stderr の末尾 500 文字を ERROR ログに出したうえで例外を送出する。

9. エラーハンドリング

方式内に try/except によるリカバリ・リトライは持たない（ffmpeg 失敗時のログ出力後の再送出を除く）。Secret 取得失敗・API 例外・音源 0 件・S3 取得失敗・合成失敗・ffmpeg 失敗はすべて送出し、共通骨格が prompt_config 単位で捕捉 → connection.rollback() でトランザクションを戻してスキップする。これにより last_used_at の更新だけが残る中途半端な状態は発生しない。未完了の prompt_config が残ればバッチは失敗終了し、Step Functions の Retry → 失敗アラーム通知につながる。
