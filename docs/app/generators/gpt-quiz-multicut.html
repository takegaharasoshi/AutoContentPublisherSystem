1. 方式概要

人間レビュー済みの問題ストック（quiz_stock_items）から LRU 順繰りで 1 問を取得し、情景イラスト 1 枚（画像生成 API）・固定キャラアセット（4 表情）・日本語フォントを Pillow のプログラム組版で時間帯スロット別のカード画像に合成し、ffmpeg の多カット連結 + BGM/SE ミックスで 16 秒・4 カット構成・1080x1920 の MP4（リール用動画）を返すクイズ方式。答え・解説は動画に載せず、投稿キャプション側で開示する（batch-flow.html セクション 3.3）。出題の型（L1 論理パズル / L3 フェルミ推定）・BGM・配色・時間帯ラベルは、実行予定時刻から決定的に解決するスロット（朝 / 昼 / 夜）で切り替える（生活溶け込み拡張。15-9 / 15-10 決定）。Phase 15-6 で実装・15-14 で logic-training-1 が本採用となり、16-1 でスキップ率 95% を受けたテコ入れ（ストック方式への転換・カット構成刷新・答えのキャプション移動）を設計 Fix した。

3. 入力（parameters とスロット解決）

parameters のキーは以下のとおり。検証に通らない値は起動直後に RuntimeError となる。

キー必須内容
slots必須（1 件以上）時間帯スロットの配列。各要素は from_jst_hour（0〜23 の整数）・quiz_type（L1 / L3）・difficulty・slot_code（morning / noon / night = コード側パレット定義に存在すること）・slot_label（時間帯ラベルピルの表示文言）の 5 フィールド必須（欠落・空文字・未知の slot_code は異常終了）。quiz_type / difficulty はストック取得の絞り込みキーを兼ねる。tone_hint は休止（存在しても無視。下記 decision）
max_regenerations任意休止（存在しても無視。再生成ループ自体が休止のため）
llm_model任意休止（存在しても無視。テキスト LLM を呼ばないため）
決定（16-1）: 休止パラメータは削除せず無視する tone_hint・max_regenerations・llm_model は生成チェーン休止（セクション 5 の decision）に伴い未使用となるが、DB の登録値は変更せず、方式側が無視する扱いとする（余分なキーをエラーにしない）。生成経路を再開する場合にそのまま有効なため。prompt_configs.prompt_text（テーマ・世界観）も同様に未使用のまま残置する。

スロット解決は context.scheduled_at の JST 時から決定的に行う: slots を from_jst_hour 昇順に並べ、「JST 時以下で最大の from_jst_hour」のスロットを選ぶ。どの境界にも達しない早朝（例: 境界 4/11/17 に対する 0〜3 時）は最後のスロットへ巻き戻す（夜スロットが翌 3:59 まで続く扱い）。Scheduler の Input にスロットは持たせず時刻だけがスロットの指定になるため、スケジュール時刻の変更はスロット変更になりうる（operation.html セクション 2.1 手順 3 の warn）。

4. 認証情報（API キー）

環境変数 API_SECRET_ARN から openai_image.load_api_key() で取得する（他方式と同一の Secret acps/{env}/image/api-key）。生成チェーン休止後に OpenAI API を呼ぶのは情景イラスト生成（Images API）のみ（クライアントのタイムアウト 300 秒）。

5. 問題ストックの取得（LRU 順繰り）

出題は人間レビュー済みの問題ストック quiz_stock_items（data-model.html セクション 4.10）から取得する。ストックの調達（リサーチ → 表現書き直し → レビュー → 投入）と補充サイクルは operation.html セクション 3。

選定クエリ（audio_assets のスロット別 LRU 選曲と同型）: スロットの quiz_type / difficulty に一致する有効ストックから、最も長く使っていない 1 問を選ぶ。MySQL の ASC ソートは NULL が先頭のため、未使用（last_used_at IS NULL）を優先し、未使用が尽きたら最古使用分を再利用する挙動がクエリ 1 本で成立する。

SELECT id, question_text, answer_text, content_fields FROM quiz_stock_items
 WHERE set_id = %s AND quiz_type = %s AND difficulty = %s AND is_active = 1
 ORDER BY last_used_at ASC, id ASC LIMIT 1
  • 0 件は RuntimeError で異常終了（BGM 選曲と同型のフェイルラウド。ストック未投入・全行無効化の検知）
  • 再利用（last_used_at IS NOT NULL の行を選んだ場合）は WARNING ログを出す（補充遅延のサイン。CloudWatch アラームは持たず、失敗通知起点の運用と週次の在庫確認で拾う）
  • 防御的フィールド検査: 取得した行の question_text / answer_text と content_fields の必須フィールド（下表）の存在・非空・文字数上限を検査し、不備は異常終了（投入ミスの検知。再生成ループはないため即フェイルラウド）
  • last_used_at / use_count の UPDATE は動画完成後に行い、commit は共通骨格に委ねる（失敗時はストック消費の副作用ごとロールバック）

フィールド仕様（content_fields JSON。文字数上限は組版・キャプションのフィッティング前提で、16-2 の執筆・投入時に遵守する）:

6. 情景イラスト生成

取得したストック問題の illustration_scene をコード側固定のイラストプロンプト（情景 + スロット別の時間帯ムード + パレット由来のブランド配色 + 禁止事項〔文字・数字・記号、答えを示唆する構図、中央への主要物配置〕）に組み込み、gpt-image-1 / 1536x1024（横長）/ medium / 1 枚で生成する。1 実行 1 枚で、全 4 カットのカード内ブロックに常駐させる（15-9 決定 → 15-14 で全面背景からカード内ブロックへ変更・横長化）。再利用時も毎回新規生成するため、同じ問題の再出題でも見た目は変わる。

決定（15-9 / 15-10）: 方式 C（文字なし情景イラスト + プログラム文字描画）の採用と失敗時の扱い 図示 3 方式の実 API 比較で、インフォグラフィック全体の画像生成（方式 B）は 4/4 枚で誤字・見切れ・答え示唆・構造崩壊のいずれかが発生し不採用。文字は 100% プログラム描画（Pillow）、イラストは文字を禁止した情景描写のみという分業に落とした。イラストのズレは「品質の傷」であって誤答ではないと整理（ユーザー決定）。illustration_scene の検証はプログラム検査（必須・最大 200 字）のみで、禁止事項・時間帯ムードはコード側固定プロンプトで担保する。イラスト生成の失敗は縮退せず異常終了（フェイルラウド。イラスト常駐の構成では欠けた状態で成立しないため）。

8. 組版（Pillow）

8.1 カット構成（16 秒・タイムラインカード 8 枚・版面固定）

全 8 枚のカードは同一版面（時間帯ラベルピル / 見出し「問題」/ 問題文 / 情景イラストブロック / コーチ + 吹き出し）で、カット間で変わるのは吹き出し文言・コーチ表情・カウントダウンバッジのみ。問題文は 1 フレーム目から最終フレームまで同座標・同サイズで表示され続ける。

カット尺カードカット間で変わる要素
1 つかみ4 秒1 枚吹き出し = hook（問題ごとの動的つかみコピー）+ コーチ hook（力こぶ）
2 考える4 秒1 枚固定吹き出し「止めてじっくり考えても OK」+ コーチ think（考え込む）
3 カウントダウン5 秒5 枚（1 秒 × 5）カウントダウン円バッジ（5→1）+ 吹き出し = hint（問題ごとの動的ヒント。5 枚とも同一文言）+ コーチ question（手のひらで差し出す）
4 誘導3 秒1 枚固定吹き出し「答えは投稿のキャプションへ！」+ コーチ answer（ガッツポーズ）
決定（16-1）: カット構成の刷新（スキップ率 95% テコ入れ） 旧構成（20 秒: つかみ 3 → 問題 7 → 考える 5 → 答え 5）はスキップ判定が起きる冒頭 1〜2 秒に問題が出ておらず、参考アカウント 4 例（すべて 1 カット目 = 問題見出し + 問題文）とも乖離していた。テコ入れ方針 4 点（development-plan.md Phase 16 冒頭）を以下のとおり落とし込んだ:
  • 1 カット目から問題を出す: 版面固定により問題文・型・難度ピルが 1 フレーム目から表示される。1 フレーム目はカバー・サムネイル兼用（カバー未指定デフォルトの仕様を能動的に利用。batch-flow.html 3.3 手順 4）
  • つかみは吹き出しで行う: 独立したつかみカット（版面）は廃止するが、カット 1 の吹き出しを問題ごとの動的つかみコピー（hook）にする。固定文では「クイズでは問題そのものが最強のつかみ」を補強できないためのユーザー指示（16-1 計画レビュー）
  • 動画内に答えを出さない: 答えカードを廃止し、answer / explanation / coach_comment はキャプションへ移動。最終カットは問題を残し吹き出しでキャプションへ誘導する（保存・コメント・キャプション開封・リピート再生の誘発を狙う）。誘導文言はストーリーズ再掲（キャプション非対応）の閲覧者にも通じる「答えは投稿のキャプションへ」系とする
  • 版面固定 + 吹き出し差し替え: カット別組版のバリエーション（15-14 で苦労した箇所）が消え、組版は 1 種類 + 差分描画に単純化。動きはゆっくりズーム + 吹き出し差し替え + カウントダウンで担保する
吹き出しの固定文 3 種（カット 2〜4）はコード側定数。尺の合計 16 秒はユーザー決定（完走ハードルを下げつつ誘導が読み切れる配分）。
決定（16-2b = 16-2 執筆中のユーザー決定〔2026-08-05 頃〕を正式反映）: 問題カットの「考える」化とカウントダウンの動的ヒント化 版面固定により問題文は 1 フレーム目から常時表示されるため、固定吹き出しだけのカット 2「問題」は情報を足していなかった。16-2 の執筆・レビュー中のユーザー決定で上表のとおり変更した:
  • カット 2 を「考える」へ: 旧カット 3 の固定文「止めてじっくり考えても OK」を前倒しし、考えるフェーズを 4 + 5 = 9 秒に拡大（旧「頭の中だけで解いてみよう」は廃止）
  • カット 3（カウントダウン）の吹き出しをストックの hint へ: 問題ごとの動的ヒント（20 字・カウントダウン中の最後の後押し）を表示する。これに合わせ全問に hint フィールドを追加した（セクション 5。初期 42 問は 16-2 で追加・レビュー済み）
  • 吹き出しは動的 2 種（hook / hint）+ 固定文 2 種（カット 2・4 = コード側定数）になる（16-1 時点の「固定文 3 種」を置き換え）
  • コーチ表情は 4 枚継続使用のまま割当を入れ替える（16-2b の整理）: カット 2 = think（考え込む = 「考える」の意味に一致）・カット 3 = question（手のひらで差し出す = ヒントの差し出し）。アセットの作り直しは不要（sets/logic-training-1.html セクション 7）
決定（16-3 = 2026-08-07 のユーザーレビュー）: 型・難度ピルの廃止 16-1 で見出し行に計画した型・難度ピルは置かない（16-3 実装のオフライン動画確認でのユーザー決定。「ない方がスッキリする」= 版面の情報過多を避ける）。出題の型は問題文自体が伝えるため表示しない。16-3 実装時に暫定定義したコード側定数 PILL_LABELS（なぞなぞ・サクッと 等）は同日中に削除し、quiz_type の検証は L1 / L3 の集合チェックへ戻した。あわせて slot_label（時間帯ラベルピル）は「朝 / 昼 / 夜の脳みそトレ」へ改名（セット側データの変更。セット別設計書セクション 4）。

8.2 レイアウトの構造保証

  • カード = ズームセーフ枠: カード矩形を kenburns と同じ導出（出力寸法 / ZOOM_END − マージン 8）で ZOOM_END=1.04 から計算し、ズーム終端でもカード全体が可視であることを構造的に保証する（1030 × 1838 中央配置）。ズームは文字の可読性優先で kenburns（1.08）より弱い
  • 本文セーフエリア: カード領域と Instagram UI 予約域（右 12% / 下 15%）の交差に文字とコーチを収める。イラストは全面背景ではなくカード内ブロックのため、文字の見切れは構造的に発生しない（プロンプト側のセーフエリア指定は不要）
  • 見出し行: 見出し「問題」（左アクセントバー）のみを全カット共通で常設する。型・難度ピルは置かない（16-1 で計画したが 16-3 のユーザーレビューで廃止 = 下記 decision）
  • スロット別パレット: 背景 / カード / 本文 / 補助文字 / アクセント / 装飾の 6 色をコード側定数 SLOT_PALETTES で持つ。朝 = クリーム、昼 = ライトブルー（15-13 でユーザー決定により夜と差別化）、夜 = ダークネイビー。アクセントはアンバー系で統一
  • 共通デザイン要素（15-14 の投稿前レビューで確定）: 時間帯ラベル = テキスト幅ピル + アクセントドット（上部中央）・見出し = 左アクセントバー・カウントダウン = アクセント色の円バッジ（直径 150）に白抜き（位置は見出し行の右端。バッジの数字も文字のためカード右端ではなくセーフエリア右端に合わせる = 16-3 レビューでの修正）・イラスト = 角丸 + 装飾色の縁取り・コーチのセリフ = 全カットで吹き出しに統一（動的 2〔hook / hint〕+ 固定文 2。16-2b で変更）
  • コーチ配置: 4 枚の不透明領域の和で共通矩形をトリミングし（相対サイズ・立ち位置を保存）、300 × 430 の枠へ contain してカード下端基準（下端から 140px）の右下に置く。カット間で大きさ・立ち位置が動かない
  • イラストブロックの 2 パス描画: 1 巡目はイラストなしで全カットを描いて最も低いテキスト下端を測り、2 巡目でテキスト下端 + 48px からコーチ上端 − 16px までの横長ブロックを全カット共通の位置に敷いて本描画する（カット間でイラストが動かず、吹き出しとカウントダウンだけが変わる）。ブロック高が 200px 未満になる場合は異常終了（テキスト過多の検知。版面から答え・解説が消えたため旧構成より発生しにくい）
  • テキストフィッティング: 実測幅による 1 文字ずつの折り返し + 禁則処理（行頭の句読点・閉じ括弧、行末の開き括弧を分割位置の追い出しで回避。15-13 追加）。割当高さに収まるまでフォントを 2pt 刻みで縮小し、下限 30pt でも収まらなければ異常終了（フェイルラウド）

9. ffmpeg 合成

2 段構成。①カード 8 枚を1 枚ずつズーム付きセグメント MP4 にエンコードし、②concat demuxer で無劣化連結（-c:v copy）しながら音声 3 系統をミックスする。

工程値（実装定数）

連結concat demuxer + -c:v copy（再エンコードなし）+ +faststart・全体 -t 16
BGM-stream_loop -1 でループ入力し 16 秒でトリム。音量 1.0（前処理済み・-14 LUFS 前後）。afade=t=out（st=15・d=1）を適用（素材は 20 秒尺のため前処理側の終端フェードがトリムで失われる。16-1 追加）

11. エラーハンドリング

生成チェーン休止により方式内のリカバリループは存在しない。異常（parameters 不正・アセット欠落・BGM 0 件・ストック 0 件・ストック行のフィールド不備・イラスト生成失敗・組版の収まり不足・ffmpeg 失敗）はすべて例外を送出し、共通骨格が prompt_config 単位で捕捉 → connection.rollback() でトランザクションを戻してスキップする。quiz_items INSERT・ストック / BGM の last_used_at 更新はロールバックで消えるため中途半端な状態は残らない。未完了の prompt_config が残ればバッチは失敗終了し、Step Functions の Retry → 失敗アラーム通知につながる。
