方式設計書: gpt-quiz-multicut

Fix（15-16 で作成） 方式名（レジストリキー）: gpt-quiz-multicut 最終更新: 2026-07-29
本書の位置づけ 生成方式 gpt-quiz-multicut の方式固有仕様（LLM 生成・検証チェーン・スロットだし分け・組版・ffmpeg 合成）を記録する。全方式共通の契約（方式インターフェース）と方式カタログは batch-flow.html セクション 2.1、分冊ルール（1 方式 1 本・本採用時に作成）は design-outline.html セクション 1.1 を参照。本書は実装（services/image-batch/app/generators/gpt_quiz_multicut.py）を正として記述している。設計の経緯は 15-5 / 15-9 / 15-10 の設計 Fix（壁打ち記録・development-log.md）にある。

1. 方式概要

LLM テキスト API でクイズ（問題・答え・解説等の構造化フィールド）を生成し、決定的検証 + 独立 LLM 検証 + 重複検査に通った出題だけを採用したうえで、情景イラスト 1 枚（画像生成 API）・固定キャラアセット（4 表情）・日本語フォントを Pillow のプログラム組版で時間帯スロット別のカード画像に合成し、ffmpeg の多カット連結 + BGM/SE ミックスで 20 秒・4 カット構成・1080x1920 の MP4（リール用動画）を返すクイズ方式。出題の型（L1 論理パズル / L3 フェルミ推定）・口調・BGM・配色・時間帯ラベルは、実行予定時刻から決定的に解決するスロット（朝 / 昼 / 夜）で切り替える（生活溶け込み拡張。15-9 / 15-10 決定）。Phase 15-6 で実装、15-11 でスロットだし分け + イラスト常駐へ拡張、15-14 で logic-training-1 が実投稿に成功し本採用となった。

2. 契約の実装

共通の契約（batch-flow.html「生成方式の契約」）を generate(context: GeneratorContext) -> GeneratorResult で実装する。冪等性（完了判定）・S3 保存・DB 登録・トランザクション制御は共通骨格（processing.py）の責務であり、本方式は関与しない。

処理順序: ① parameters 検証 → ② スロット解決 → ③ 固定アセットの事前検査（フォント → set_code → コーチ 4 枚 → SE 2 種 + BGM 選曲。LLM を呼ぶ前に欠落をフェイルラウドさせ、API 費を無駄にしない）→ ④ 出題履歴取得 → ⑤ 生成・検証ループ（セクション 5）→ ⑥ 情景イラスト生成（セクション 6）→ ⑦ Pillow 組版（セクション 8)→ ⑧ ffmpeg 合成（セクション 9）→ ⑨ quiz_items INSERT + last_used_at 更新 → ⑩ GeneratorResult を返す。

3. 入力（parameters とスロット解決）

prompt_configs.prompt_text にはセットのテーマ・世界観と題材の条件だけを書く。出力フィールドの必須・文字数・L1 DSL の書式・禁止事項・イラスト生成プロンプトはコード側が固定で持ち、DB 側と二重に書かない（15-5 決定）。parameters のキーは以下の 3 つで、検証に通らない値は起動直後に RuntimeError となる。

キー必須内容
slots必須（1 件以上）時間帯スロットの配列。各要素は from_jst_hour（0〜23 の整数）・quiz_type（L1 / L3）・difficulty・slot_code（morning / noon / night = コード側パレット定義に存在すること）・tone_hint（口調の方向性。生成プロンプトへ差し込む）・slot_label（時間帯ラベルピルの表示文言）の 6 フィールドすべて必須（欠落・空文字・未知の slot_code は異常終了）
max_regenerations任意（既定 3）再生成の上限回数（試行回数は +1 回。logic-training-1 は 15-13 の実測を受け 5）
llm_model任意（既定 gpt-5.6-terra）テキスト生成・検証に使う OpenAI モデル名（生成と検証で同一モデル）

スロット解決は context.scheduled_at の JST 時から決定的に行う: slots を from_jst_hour 昇順に並べ、「JST 時以下で最大の from_jst_hour」のスロットを選ぶ。どの境界にも達しない早朝（例: 境界 4/11/17 に対する 0〜3 時）は最後のスロットへ巻き戻す（夜スロットが翌 3:59 まで続く扱い）。Scheduler の Input にスロットは持たせず時刻だけがスロットの指定になるため、スケジュール時刻の変更はスロット変更になりうる（operation.html セクション 2.1 手順 3 の warn）。

4. 認証情報（API キー）

環境変数 API_SECRET_ARN から openai_image.load_api_key() で取得する（他方式と同一の Secret acps/{env}/image/api-key）。テキスト生成・独立検証・イラスト生成のすべてを同じ OpenAI クライアント（タイムアウト 300 秒）で呼ぶため、Secret は 1 件で足りる。

5. 問題生成と検証チェーン

LLM の誤答をそのまま投稿しないことが本方式の急所（15-1 の評価軸 G）。生成のたびに以下を全通過した出題だけを採用し、不合格は理由をログに出して再生成する。

5.1 生成（構造化フィールド方式）

生成プロンプトは「prompt_text（テーマ・世界観）+ コード側固定の生成指示（フィールド仕様・L1 DSL の正準形・L3 の書式・禁止事項）+ スロットの型/難度/tone_hint + 直近要旨（重複禁止リスト）+ 試行番号」を結合して組み立て、Responses API に json_object 形式で 1 オブジェクトを要求する。必須フィールドと文字数上限:

フィールド上限用途
hook20 字カット 1 の呼びかけ（tone_hint を反映）
question90 字問題文（カット 2・3）
answer30 字答え（カット 4）
explanation80 字解説（カット 4）
coach_comment30 字答えカットのコーチ吹き出し（tone_hint を反映）
tags10 字 × ちょうど 3 個記録用（キャプションは固定テンプレートのため未使用）
summary100 字出題要旨（重複禁止リストの単位）
illustration_scene200 字情景イラストの描写（セクション 6）
machine_spec / machine_answer—L1 のみ必須（5.2）

5.2 決定的検証（プログラム検査）

  • フィールド検査: 必須・型・文字数上限・tags の個数（illustration_scene は strip 後に空なら不合格）
  • L1 = 閉じた DSL の全列挙検証: machine_spec は truth_tellers（正直者・嘘つき）/ ordering（順序）/ matching（対応づけ）の 3 種だけを受け付ける閉じた JSON DSL（ソースコードの評価はしない）。要素は最大 5 件で、全割当・全順列を全列挙し、唯一解であることと machine_answer（正準形）が唯一解と一致することを検査する。未知の語彙・不正参照・解なし・複数解はすべて不合格
  • L3 = 書式検査: answer は正規表現で「約<数値と単位>（目安）」の形を強制する（断定表現の禁止はプロンプト側）

5.3 独立 LLM 検証（答えを伏せた別解答）

  • L1: 生成側の答えを見せず問題文だけを独立の LLM に解かせ、返ってきた machine_answer が全列挙で得た唯一解と一致するかを見る（問題文だけで解けること = 文章化の欠落検知を兼ねる）
  • L3: 問題文 + 推定ルート（explanation。最終回答値は非表示）を渡して独立に推定させ、①route_valid が true ②推定値が正の有限値 ③生成側 answer の数値（万・億・兆の単位換算込み）と桁オーダー（log10 の床）が一致、の 3 点で判定する

5.4 重複検査

二段構え。①生成プロンプトに直近の summary 30 件を重複禁止リストとして差し込む（予防）②生成後に直近の question_text 120 件と文字バイグラムの Jaccard 類似度を取り、0.55 以上で不合格にする（検知。比較前に NFKC 正規化 + 空白・約物除去）。履歴はどちらも set_id × quiz_type スコープで quiz_items から取得する。

5.5 再生成とフェイルラウド

不合格（検証 NG・JSON パース不能）は WARNING ログ（試行番号 + 理由）を出して再生成する。max_regenerations を使い切ったら RuntimeError で異常終了し、その回は投稿しない（誤答を出すより落とす。15-5 決定）。再生成回数・NG 理由は DB に記録せず CloudWatch Logs のみで観測する（設計課題リスト 2026-07-27）。

6. 情景イラスト生成

採用した出題の illustration_scene をコード側固定のイラストプロンプト（情景 + スロット別の時間帯ムード + パレット由来のブランド配色 + 禁止事項〔文字・数字・記号、答えを示唆する構図、中央への主要物配置〕）に組み込み、gpt-image-1 / 1536x1024（横長）/ medium / 1 枚で生成する。1 実行 1 枚で、全 4 カットのカード内ブロックに常駐させる（15-9 決定 → 15-14 で全面背景からカード内ブロックへ変更・横長化）。

決定（15-9 / 15-10）: 方式 C（文字なし情景イラスト + プログラム文字描画）の採用と失敗時の扱い 図示 3 方式の実 API 比較で、インフォグラフィック全体の画像生成（方式 B）は 4/4 枚で誤字・見切れ・答え示唆・構造崩壊のいずれかが発生し不採用。文字は 100% プログラム描画（Pillow）、イラストは文字を禁止した情景描写のみという分業に落とした。イラストのズレは「品質の傷」であって誤答ではないと整理（ユーザー決定）。illustration_scene の検証はプログラム検査（必須・最大 200 字）のみで、禁止事項・時間帯ムードはコード側固定プロンプトで担保する。イラスト生成の失敗は縮退せず異常終了（フェイルラウド。イラスト常駐の構成では欠けた状態で成立しないため）。

7. 固定アセットと選曲

いずれも最初の LLM 呼び出しの前に取得・検査する（欠落の早期フェイルラウド）。

アセット取得元検査

スロット別 LRU 選曲（V004 の audio_assets.time_slot。15-10 決定）: 当該スロット一致または time_slot IS NULL（スロット非対応の既存登録との後方互換）の有効 BGM から、最も長く使っていない 1 曲を選ぶ。

SELECT id, s3_key FROM audio_assets
 WHERE set_id = %s AND asset_type = 'bgm' AND is_active = 1
   AND (time_slot = %s OR time_slot IS NULL)
 ORDER BY last_used_at ASC, id ASC LIMIT 1

last_used_at の UPDATE は動画完成後に行い、commit は共通骨格に委ねる（失敗時は選曲の副作用ごとロールバック）。音源の前処理レシピ（20 秒尺の 2 パス loudnorm・SE はピーク調整のみ）と証跡管理は operation.html セクション 3。

8.1 カット構成（20 秒・タイムラインカード 8 枚）

カット尺カード内容

8.2 レイアウトの構造保証

  • カード = ズームセーフ枠: カード矩形を kenburns と同じ導出（出力寸法 / ZOOM_END − マージン 8）で ZOOM_END=1.04 から計算し、ズーム終端でもカード全体が可視であることを構造的に保証する（1030 × 1838 中央配置）。ズームは文字の可読性優先で kenburns（1.08）より弱い
  • 本文セーフエリア: カード領域と Instagram UI 予約域（右 12% / 下 15%）の交差に文字とコーチを収める。イラストは全面背景ではなくカード内ブロックのため、文字の見切れは構造的に発生しない（プロンプト側のセーフエリア指定は不要）
  • スロット別パレット: 背景 / カード / 本文 / 補助文字 / アクセント / 装飾の 6 色をコード側定数 SLOT_PALETTES で持つ。朝 = クリーム、昼 = ライトブルー（15-13 でユーザー決定により夜と差別化）、夜 = ダークネイビー。アクセントはアンバー系で統一
  • 共通デザイン要素（15-14 の投稿前レビューで確定）: 時間帯ラベル = テキスト幅ピル + アクセントドット（上部中央）・見出し = 左アクセントバー・カウントダウン = アクセント色の円バッジ（直径 150）に白抜き・イラスト = 角丸 + 装飾色の縁取り・コーチのセリフ = 全カットで吹き出しに統一（固定文 3 + LLM の coach_comment）
  • コーチ配置: 4 枚の不透明領域の和で共通矩形をトリミングし（相対サイズ・立ち位置を保存）、300 × 430 の枠へ contain してカード下端基準（下端から 140px）の右下に置く。カット間で大きさ・立ち位置が動かない
  • イラストブロックの 2 パス描画: 1 巡目はイラストなしで全カットを描いて最も低いテキスト下端を測り、2 巡目でテキスト下端 + 48px からコーチ上端 − 16px までの横長ブロックを全カット共通の位置に敷いて本描画する（カット間でイラストが動かず、テキストとコーチだけが変わる）。ブロック高が 200px 未満になる場合は異常終了（テキスト過多の検知）
  • テキストフィッティング: 実測幅による 1 文字ずつの折り返し + 禁則処理（行頭の句読点・閉じ括弧、行末の開き括弧を分割位置の追い出しで回避。15-13 追加）。割当高さに収まるまでフォントを 2pt 刻みで縮小し、下限 30pt でも収まらなければ異常終了（フェイルラウド）

9. ffmpeg 合成

2 段構成。①カード 8 枚を1 枚ずつズーム付きセグメント MP4 にエンコードし、②concat demuxer で無劣化連結（-c:v copy）しながら音声 3 系統をミックスする。

工程値（実装定数）
セグメント（8 本）静止画入力（-loop 1 -framerate 30 -t 尺）→ 2 倍スーパーサンプリング → zoompan（1.0 → 1.04・中央固定・s=1080x1920・fps=30）→ libx264 / -crf 20 / -preset medium・映像のみ
連結concat demuxer + -c:v copy（再エンコードなし）+ +faststart・全体 -t 20
BGM-stream_loop -1 でループ入力し 20 秒でトリム。音量 1.0（前処理済み・-14 LUFS 前後）
SE: カウントダウンティックadelay=10000（考えるカット開始 = 10 秒地点から 5 打）・音量 −6 dB
SE: 正解チャイムadelay=15000（答えカット開始 = 15 秒地点）・音量 −3 dB
ミックスamix=inputs=3:normalize=0（自動正規化を切り、前処理済みラウドネスを保つ）→ 20 秒トリム → AAC 再エンコード（ミックスするため kenburns の -c:a copy は使えない）
タイムアウト・検査各 ffmpeg 呼び出し 600 秒。非ゼロ終了・タイムアウトは stderr 末尾 500 字を ERROR ログに出して送出。空ファイル出力も異常終了

11. エラーハンドリング

方式内のリカバリは生成・検証ループの再生成のみで、それ以外（parameters 不正・アセット欠落・BGM 0 件・イラスト生成失敗・組版の収まり不足・ffmpeg 失敗）はすべて例外を送出し、共通骨格が prompt_config 単位で捕捉 → connection.rollback() でトランザクションを戻してスキップする。quiz_items INSERT・last_used_at 更新はロールバックで消えるため中途半端な状態は残らない。未完了の prompt_config が残ればバッチは失敗終了し、Step Functions の Retry → 失敗アラーム通知につながる。
