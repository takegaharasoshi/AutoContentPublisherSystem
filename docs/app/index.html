要約

このページはアプリ設計（docs/app/）の目次。アプリ設計は、配信面のバッチがアプリとして何をするか（処理・データ・運用）と、セット・生成方式ごとの仕様を持つ。基本設計（全体）7 章 詳細設計への入口から来るページで、各機能の入口は機能別の基本設計（投稿 / インサイト収集 / コメント自動返信 / トークン更新）にある。下の表は、何を見たいときにどのページを開くかをまとめたもの。

判断の記録

本文の「→ 理由 D-xx」から飛んでくる先。なぜそうしたかをここにまとめる。

D-01 アプリ設計は大枠 → 詳細の 2 段階で行った

決めたこと
大枠（Phase A: 仕様の壁打ち・設計書構成・主要方針の骨子）と詳細（Phase 9: テーブル定義・処理フローの詳細・DDL）の 2 段階で設計し、インフラ構築の知見を Phase 10-1 で反映して最終 Fix とした。以後の改訂は各設計書の判断の記録と開発記録に残す
理由
上流工程に適した生成 AI モデルの利用期限を機に、詳細設計をインフラ構築（Phase 0〜8）より前へ前倒ししたため、インフラの知見を後から反映する段を設けた
日付・出典
Phase A（2026-07-06）→ Phase 9（2026-07-06〜07）→ Phase 10-1（2026-07-15）。経緯は開発記録
