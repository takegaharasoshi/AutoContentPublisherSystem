1. 評価軸（15-1 で確定）

開発計画 15-1 で指定済みの 4 軸に、壁打ちで運用系 3 軸を追加し 7 軸で確定した（2026-07-26 ユーザー承認）。15-2 以降の判断もこの軸で行う。

軸判定の中身
A. リーチを狙える広い層に刺さり、保存・シェア・ループ再生・コメントを誘発する構造がある。Meta ボーナスは 100 万再生規模が必要（事業戦略書 2）なので天井の高さを重視
B. 独自の世界観一目で「あのアカウント」と分かる統一スタイル。テンプレ的な「低労力 AI コンテンツ」に見えないこと（Meta のリーチ抑制・収益化除外対策。事業戦略書 2 の必須要件）
C. 生成 AI での再現安定性構図・スタイルが毎日ブレずに全自動で量産できる。キャラクター同一性維持・正確なテキスト描画など生成 AI の苦手領域を構造的に踏まない
D. 既存セットとの差別化fantasy-animals-1（写真風のかわいい架空動物 + 図鑑テキスト + Ken Burns）とテーマ・見た目・生成方式のいずれでも被らない
E. ネタ枯渇耐性（追加）全自動で毎日生成し続けるため、プロンプト設定から半永久的にバリエーションが湧く構造が必要。数十本で打ち止めになるテーマは不可
F. 新生成方式との相性（追加）15-3 で決める「静止画合成の高度化」（複数カット構成・多段生成チェーン等）が見せ場として活きるテーマか。カット間に物語的なつながり（ズーム・変化・展開）があるほど良い
G. 権利・炎上リスクの低さ（追加）実在人物・実在ランドマーク・誤情報に見える合成・音源権利などの地雷をテーマ側で構造的に回避できる（全自動運用では投稿前の人間チェックが薄いため）

2. 前提決定: 言語戦略（15-1）

decision: 勝負セットは日本語コンテンツとする（2026-07-26 ユーザー決定） Claude は「言語非依存ビジュアル型（グローバルリーチで天井最大化）」を推奨したが、ユーザー判断で日本語コンテンツ（国内向け）に決定。 リーチ天井はグローバル比で下がるが、国内層に深く刺さり濃い反応（コメント・保存）を取りやすい路線を選ぶ。 この決定が後続のテーマ絞り込み（日本語テキスト主体のテーマが許容される）の前提となった。

3. 候補の発散（15-1 第 1 巡）

3.1 リーチ動向の調査所見（2026-07-26 時点）

  • フェイスレス / AI 活用リールは 2026 年時点で定着し、心理学・雑学 facts・satisfying・自己啓発系が定番の高エンゲージメントジャンル。新規クリエイターアカウントの過半がフェイスレス設計との推計もある

4. 方向転換: 「社会人向けロジカルトレーニング」（15-1 第 2 巡）

第 1 巡の絞り込み（Claude 暫定推し: #1 > #2 > #3）に対し、ユーザーから「1 日 3 回 社会人のためのロジカルトレーニング」のイメージが提示され、方向転換した。クイズ形式として捉え直すと 7 軸評価は以下のとおりで、有望方向として妥当と判断した。

軸評価根拠
A. リーチ○「問題 →（考える間）→ 答え」は答えを見るまで離脱しない構造。視聴維持・再視聴・コメント（回答宣言）を構造的に誘発。自己啓発・スキル系は保存率が高い定番ジャンル。日本語圏の天井はセクション 2 の決定どおり受容
B. 独自世界観△最大の設計課題。文字カード型クイズは「テンプレ量産 AI」に最も見えやすい。世界観の被せ方はキャラクター主軸で対策（セクション 5）
C. 再現安定性◎問題文・選択肢はプログラム側で組版（Pillow テキスト合成）すれば文字化けリスクゼロ。gpt-image に文字を描かせる既存セット方式より安定
D. 差別化◎図鑑（癒し・眺める）と完全に別ジャンル（実用・参加する）。生成方式も変わる
E. ネタ枯渇耐性◎問題は LLM で無限生成可能。ただし出題履歴の重複管理が必要（持ち越し論点）
F. 新方式相性◎「問題カット → ヒントカット → 答え・解説カット」の複数カット構成そのもの。多段生成チェーン（LLM 問題生成 → 背景生成 → 組版合成 → カット連結）と完全に一致
G. リスク○実在物・音源・誤情報系の地雷なし。唯一の急所は誤答リスク（下記 warn）
急所: 答えの正しさの担保（15-3 / 15-4 へ持ち越し） 全自動運用で論理問題の誤答を投稿すると、コメント欄で即座に指摘されアカウントの信頼が一撃で毀損する。 gpt-image に問題テキストを作らせるのは論外で、LLM の問題生成にも対策設計が必須:
  • 候補 1: 生成した問題を別プロンプトで解かせて一致確認する自己検証（全自動を維持）
  • 候補 2: 事前生成ストック + 定期的な人間レビューからの配信（全自動性を一部緩める）
  • フェルミ推定（L3）は答えが幅で許されるため誤答リスクが構造的に低い、という編成上のヘッジも効く

5. 15-1 の決定事項（絞り込み結果）

decision: 有望案と世界観の主軸（2026-07-26 ユーザー決定）
  1. テーマ方向 = 社会人向けロジカルトレーニング（クイズ・出題形式のリール）に絞る。視覚系候補（#1 ミニチュア無限ズーム等）は保険として残さず一本化。15-2 の試し生成で詰まった場合は 15-1 に戻って再発散する
  2. 有望案 = L1（論理パズル・謎解き）+ L3（フェルミ推定・数字感覚）のミックス編成。時間帯・曜日で型を回す（例: 朝 = 軽い L1、昼 = L3、夜 = じっくり）。型の比率・実在性は 15-2 の試し生成で検証する。L2（仕事の思考法ミニケース）は 1 問の情報量がリール尺に対して過大なため見送り
  3. 独自世界観（B 軸）はキャラクターを立てる方式を主軸とする。出題者ペルソナを固定し、キャラ画像は少数を作り込んで固定アセット化し合成で使い回す（毎回 gpt-image に描かせるとブレるため。C 軸対策と両立）。キャラ設定・デザインは 15-2 で試し生成する
  4. 「1 日 3 回」（朝・昼・夜）は習慣化ブランディングとして有力。テキスト組版主体なら画像生成 API 費がほぼ掛からず、1 日 3 回でも現行セットよりコストが下がる見込み。頻度の確定は 15-4

7. 15-2 テーマ・世界観の確定（壁打ち 2 巡 + 試し生成）

7.1 試し生成の経緯（実 Images API・計 11 回・使い捨てスクリプト非コミット）

キャラクター候補をフラットベクター調・ネイビー×アンバーの 2 トーン統一パレット・透過背景で生成し、目視評価 → ユーザー確認を 2 巡行った。生成画像はローカル plans/15-2-trial/（gitignore 済み）に保存し、コミットしない（14-11 の試し打ちと同じ扱い）。

  • 第 1 巡（3 案）: A フクロウ博士 / B スーツの動物先輩 / C パズルピース頭のロボ。Claude は C を推したが、ユーザーフィードバックで「トレーニングが分かる、体育会系のコーチ的キャラ」へ方向修正
  • 第 2 巡（3 案）: D 脳みそコーチ（ヘッドバンド + ホイッスル + 力こぶ）/ E ゴリラコーチ / F 人間の熱血コーチ → D 脳みそコーチをユーザー決定（「脳を鍛える = 頭の筋トレ」の記号性がテーマと完全一致し、独自性・差別化とも最強）
  • ポーズ展開の検証（C 軸の急所）: images/edits の参照画像方式で D の「考え中」「正解」ポーズを生成し、脳の形・ヘッドバンド・ホイッスル・体型の同一性が維持されることを確認。固定アセット方式（少数を作り込んで Pillow 合成で使い回す）が成立すると判断した
試し生成で得た技術知見 3 点（15-9 のアセット制作への引き継ぎ）
  1. gpt-image-2 は透過背景非対応（API がエラーを返す）。固定アセット制作は透過対応の gpt-image-1 を使う。アセット制作は一回きりの作業で夜間パイプライン外のため、プロバイダ/モデル構成への影響はない
  2. gpt-image-1 でも透過指定が確率的に無視されることがある（試行 11 回中 1 回、全面不透明で返却）。アセット制作時はアルファチャンネル検査 + リトライで対処する
  3. ポーズ展開時に細部が揺れる（頭のパズル凸部の消失・ヘッドバンドの縞色変化等）。本採用キャラはリファレンスシート化（確定デザイン 1 枚を常に参照画像に使う + 細部を文言で固定）で抑える（15-9）

7.2 L1 / L3 出題サンプルの検証

  • L1（論理パズル）: 「A・B・C のうち正直者は 1 人だけ。A『B は嘘つき』B『C は嘘つき』C『A も B も嘘つき』。正直者は？」— 全 3 通りの場合分けで B のみ無矛盾（一意解）であることを検証。この粒度（10〜20 秒で考えられ、場合分けで機械的に検証可能）なら LLM 自己検証で誤答リスクを潰せる感触を得た（対策の本設計は 15-3）
  • L3（フェルミ推定）: 「日本にある車両用信号機は約何基？」— 推定ルート（交差点数 × 設置数）で 10 万〜数十万のオーダーに到達でき、実数（約 21 万基）を「答えの幅」で示せる構造を確認。誤答リスクが構造的に低いというヘッジも再確認

8. 15-3 コンテンツフォーマットと新生成方式の選定（壁打ち 2 巡）

8.1 決定: コンテンツフォーマット = 20 秒・4 カット

decision: 尺・カット構成（2026-07-26 ユーザー決定） 基本形は 約 20 秒・4 カット。15-1 の調査所見（成果が出やすい尺 15〜30 秒・冒頭 3 秒が勝負・ループ構造が完視聴率に効く）を 15-3 時点の再調査でも裏付けたうえで、「考える時間を確保しつつ完視聴率を守る」バランスとして選定した。各カットの秒数は 15-9 の試し打ちで微調整する。
カット尺（目安）内容コーチのポーズ
1. フック0〜3 秒タイトルカード（「今日の脳トレ」+ 型ラベル・難易度）フック用（構え）
2. 問題3〜10 秒問題カード全文出題
3. 考える10〜15 秒カウントダウン 5 秒（1 秒刻みのカード差し替えで演出）+「⏸ 止めてじっくり考えても OK」考え中
4. 答え15〜20 秒正解 + 一言解説 + 締めカード（フックと同型にしてループを閉じる）正解

8.2 決定: 生成方式 = gpt-quiz-multicut（多段生成チェーン）

decision: 方式名と方式の骨格（2026-07-26 ユーザー決定） 方式名（レジストリキー）= gpt-quiz-multicut（既存規約〔プロバイダ + 技法〕に整合。クイズ検証などテーマ固有ロジックを含む実態に対して正直な命名）。骨格は以下の 6 段チェーン。
  1. 型選択 — L1（論理パズル）/ L3（フェルミ推定）のローテーションを方式内で決定（quiz_items 履歴から least-recently-used）
  2. 問題生成（LLM） — 構造化フィールド方式: レイアウトは固定テンプレートとし、LLM は最大字数付きのフィールド（フック文・問題文・答え・解説・コーチの一言・タグ）だけを JSON で書く（組版崩れを構造的に防ぎつつ言い回しは毎回変わる = B 軸対策）
  3. 自己検証（LLM + プログラム） — 別呼び出しの LLM に答えを見せずに解かせて一致確認。L1 は可能な限り機械検証（場合分け全列挙をコードで確認）を併用。字数制約・必須フィールドはプログラム検査。NG は再生成（上限 N 回、尽きたらフェイルラウド）
  4. 重複検査 — quiz_items の直近履歴をプロンプトに除外指定 + 生成後の類似度検査（実装方式は 15-5）
  5. 組版（Pillow） — 完全プログラム組版（画像生成 API 不使用）。背景もフラットデザインを Pillow で描画（ネイビー×アンバー + 幾何学装飾）。脳みそコーチ固定アセット + 日本語フォント（Noto Sans JP 想定）を合成しカット 4 種を生成
  6. 動画化（ffmpeg） — カットごとの微ズーム（gpt-image-kenburns のスーパーサンプリング/zoompan 資産を再利用）→ トランジション連結 → BGM 多重化（audio_assets 順繰り選曲を踏襲）→ 1080x1920 MP4
  • 構造判断: 稼働 prompt_config は 1 セット 1 件を維持し、L1/L3 の出し分けは方式内ローテーションとする（複数 prompt_config 有効化は 1 実行複数メディアとなり「1 実行 1 投稿」前提と衝突するため。型構成・比率は parameters JSON で持つ）
  • LLM は OpenAI テキスト API・既存キー共用（acps/{env}/image/api-key）。モデル名は parameters で差し替え可能とし、具体名・単価は 15-5 で最新確認
  • 中間生成物 = カット画像 4 枚を S3 に保存（既存 IntermediateOutput の仕組み）。15-10 の投稿前レビューを「動画を見ずにカード画像で確認」できる

8.3 決定: 誤答リスク対策 = 完全自動（LLM 自己検証のみ）

decision: 全自動を維持し、慣らし目視期間は置かない（2026-07-26 ユーザー決定） 15-1 の候補 1（その場生成 + LLM 自己検証）を採用し、候補 2（人間レビュー付きストック配信）と Claude 提案の折衷案（投入直後 2〜4 週の投稿前レビュー継続）は不採用。検証プロンプトの穴を本番で踏むリスクは許容する。 残存リスクへの構造ヘッジ 2 点を設計原則として 15-5 へ引き継ぐ:
  1. L1 は機械検証可能な型（場合分け全列挙で一意解を確認できる論理パズル）に出題ドメイン自体を寄せる
  2. L3 の実数アンカーは「約◯◯（目安）+ 推定ルート」の幅表現に統一し断定しない（唯一残る誤情報経路をテーマ側で潰す G 軸対策）
