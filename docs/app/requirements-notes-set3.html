1. 巡 1: 構造の決定（フォーマット軸・キャラ役割・尺方針）

決定項目の依存関係（フォーマットと尺がキャラ・ナレーションの設計を拘束する）に従い、壁打ちを 3 巡（構造 → キャラ・ビジュアル → 名前・運用）に分けて実施した。巡 1 の判断材料は以下の 3 点。

  • 16 秒版面は既に窮屈: 地図ルーレット型プロトは 1 位確定が 13.5 秒で残り 2.5 秒しかなく、セリフ単位 TTS のフルナレーション（方針⑦）は 16 秒に載らない。参照動画分析でも「47 県全塗りは約 24 秒必要」との見立て
  • TOP5 ルーレット型は参照動画の最強機構「地理順逐次開示 = 自分の県が必ず出る」を継承しない（画面に出るのは 5 県のみ）。一方で「下位を晒さない」標準版面のため △ 判定ネタ（上位のみ発表が条件の 8 件）にもそのまま使え、ネタ判定作業も軽くなる（ネタ帳 neta-30.md の結論と整合）
  • 現プロトの版面にキャラの置き場所がない（上: タイトル / 中: 地図 820px / 下: 行 5 段 + CTA + 出典で埋まっている）。キャラの役割の決め方でレイアウト再設計の要否が決まる
decision: 巡 1 の 3 決定（2026-08-10 ユーザー決定）
  1. 演出フォーマットの軸 = TOP5 地図ルーレット型（唯一の本組みフォーマットとして 2 尺検証まで進める）。ランキング行型（プロト A）は単独フォーマットとしては採用せず、地図型下段の部品として吸収。全県塗り型（地理順逐次着色）は 17-2 で設計だけ起こし、定常運用後の第 2 フォーマット候補として追加判断する
  2. キャラクターの役割 = ナレーター専任 + 画面隅に小さめ立ち絵で常駐（2〜3 ポーズ差分の imagegen 静的アセット方式。logic-training-1 の固定アセット方式を転用）。版面の再設計は不要
  3. 尺方針 = 短尺 20 秒 / 長尺 30 秒の 2 尺比較・両方フルナレーション（各順位に実況が付く）。事前検証の方針⑧「16 秒 / 20〜30 秒」を修正し、16 秒版面は廃止（ナレーション前提の方針⑦を最優先）

2. 巡 2: キャラクター・ビジュアルの確定（試し生成 + 版面モック + 試聴）

2.1 キャラクター試し生成の経緯（Codex imagegen・plans/17-1-trial/ 非コミット）

15-2 と同型の「候補生成 → ユーザーフィードバック → 修正再生成」を 3 巡行った。生成は Codex 組み込みの imagegen（サブスク内・API 課金なし。16-3b と同方式）、画像はローカル plans/17-1-trial/（gitignore 済み）に保存しコミットしない。全候補を「無地濃紺背景・フラットベクター・太輪郭・2〜3 頭身・金アクセント」の統一条件で生成し、小サイズ常駐に耐えるシルエットの明快さを最重視で評価した。

  • 第 1 巡（3 案）: A 番付行司（軍配 + 裃の和風マスコット）/ B 旅する渡り鳥レポーター（帽子 + マイク + 旅かばん）/ E 表彰台の擬人化（ユーザー発案。金の 1 位表彰台に顔と手足 + マイク）。Claude は E を推奨（シルエット最強・金ボディが「1 位 = 金」のパレットに直結・テーマをキャラが体現・既存セットとの被りなし）
  • 第 2 巡（修正版 3 案）: A2 簡素化（紋様削除・3 色化 → 紺の裃が濃紺背景に溶ける新たな問題）/ B2 明色化（白ボディ + ツバメ尾羽でコントラスト解消）/ E2 和風化（赤ねじり鉢巻 + 紺法被）。ユーザーフィードバックで E 方針に確定。ただし「E2 の法被は表彰台の 2 位・3 位の段差を隠して表彰台感が失われる」との指摘を受け、段差シルエットを隠さない和風化を再検討
  • 第 3 巡（段差を隠さない和風化 3 パターン）: E3a ねじり鉢巻のみ / E3b 紅白市松トリム（段の縁に和柄帯）/ E3c 鉢巻 + 常時軍配持ち → E3a を基本形として確定し、軍配は「1 位発表ポーズ」の差分でのみ登場させる構成をユーザー決定（常駐時はクリーン、発表の瞬間に軍配が上がる = ポーズ差分が演出装置として機能）。軍配は E3c の造形が軍配らしくないとの指摘を受け、本物の行司の軍配らしい造形（瓢箪型の金団扇面 + 黒持ち手 + 朱房紐。第 1 巡 A 案の軍配が参考）に修正
  • ポーズ差分 3 種（透過版）: 基本・実況（マイク + 人差し指）/ タメ・ドキドキ（手を口元・目を見開く）/ 1 位発表（軍配を高く掲げる）を透過 PNG で生成し確認済み（e4a/e4b/e4c_*_transparent.png）
試し生成で得た技術知見（17-4 のアセット制作への引き継ぎ）
  1. Codex imagegen の透過はクロマキー背景で生成 → アルファ化の後処理方式が確実（透過指定の確率的無視への対策。15-2 知見のアルファ検査 + リトライと同系）
  2. ポーズ展開で細部（段の形状・鉢巻の結び等）が揺れる。本採用アセットは 15-9 と同様リファレンスシート化（確定デザイン 1 枚を常に参照 + 細部を文言で固定）で抑える
  3. VOICEVOX Engine は公式 Docker イメージ（CPU 版）でローカル起動でき、audio_query（速度・抑揚等のパラメータ調整可）→ synthesis の 2 API で合成できる。音素長データが取れるため方針⑦のフレーム同期の実装基盤として成立することを確認済み

2.2 パレット確定（2 案の版面モック比較）

Remotion プロトにパレット切替（src/palette.ts に共通化・inputProps で navy / wamodern を選択）とキャラオーバーレイを実装し、実レンダリングの静止画 4 枚（各パレット × ルーレット中 / 1 位発表）で比較した。

decision: パレット = 和モダン系（2026-08-10 ユーザー決定） 生成り × 藍 × 朱 × 金（bgTop #F6F0E1 / bgBottom #EFE4CC / text #24304E / accent（1 位金）#D9A62E / keyword・CTA #C73E3A / barBase #56679C ほか。モック時点の暫定値 — 正式値の確定は 17-2）。 Claude は「1 位 = 金」の演出力が最大化する濃紺系を推奨したが、明るく親しみやすい雰囲気を優先するユーザー判断で和モダン系に決定。 弱点として金が生成り地に沈む（1 位行・県名バーストのコントラスト低下）ことをモックで確認済みのため、縁取り・影等の対策を 17-2 で設計する。 背景イラスト方針（方針⑤の具体化）もこれに合わせ「生成り地 + 白系減光オーバーレイ」で確定。 背景はネタ（投稿テーマ）ごとに Codex imagegen で事前生成し、モチーフの内容はテーマ由来とする（モックの bg-wedding-light に水引・折り鶴・扇が入っているのは題材が「結婚が早い県」の例だから。固定の和風装飾を全投稿に常設するわけではない）。 スタイル固定プロンプトで固定するのは「生成り地・モチーフは四隅寄りに淡く・中央は無地の余白」という枠（版面可読性のレイアウト制約）のみ。

2.3 声の確定（VOICEVOX・4 候補試聴）

decision: TTS = VOICEVOX・声 = 白上虎太郎（2026-08-10 ユーザー決定）
  1. TTS エンジン = VOICEVOX（無料・商用可・Docker ローカル実行・音素長データでフレーム同期可）。有料サブスク型（ElevenLabs 等）は「探索期は月額固定費を積まない」原則（15-4 の Suno 見送りと同じ）により不採用。クレジット表記「VOICEVOX:白上虎太郎」をキャプションに常設する（表記位置の設計と音声ライブラリ個別規約の証跡確認は 17-2 / 17-3）
  2. 声 = 白上虎太郎（わんぱく元気な少年声。かわいい祭りマスコットの見た目との一致で選定）。候補 4 ボイス（玄野武宏 / 白上虎太郎 / 春日部つむぎ / 四国めたん）を同一セリフ・速度 1.1・抑揚 1.2 で合成して試聴比較した。スタイル・速度・抑揚の最終調整は 17-4 の本組みで行う

3. 巡 3: 名前・アカウント設計の確定

decision: キャラ名・set_code・アカウント設計（2026-08-10 ユーザー決定）
  1. キャラクター名 = 「表彰台五郎」（ひょうしょうだいごろう。ユーザー発案 — 表彰「台五郎」）。キャラ設定: 金の 3 段表彰台ボディ（段差シルエットを隠す衣装は禁止）+ 赤ねじり鉢巻 + ハンドマイク。性格 = 元気なお祭り実況キャラ。1 位発表時のみ軍配（瓢箪型 + 朱房紐）を掲げる

論点内容
