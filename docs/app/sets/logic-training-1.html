本書の位置づけ 本セット固有の設定・運用情報を記録する（15-13 で作成）。共通の処理フロー・データモデル・運用ルールは batch-flow.html / data-model.html / operation.html を参照し、本書には差分のみ書く（design-outline.html セクション 1.1）。テーマ選定・生成方式選定の検討経緯は壁打ち記録 requirements-notes-set2.html にある。

1. テーマ

社会人向けロジカルトレーニング（15-2 決定）。日本の社会人の日常を題材にしたクイズ形式の縦型ショート動画を 1 日 3 回投稿する。世界観は「毎日 3 分の頭の体操ジム」で、進行役として脳のマスコット「脳みそコーチ」（ヘッドバンド + ホイッスル + 力こぶ / フラットベクター・ネイビー × アンバー）が全カットに登場する。

出題は 2 種類（parameters.slots の quiz_type で時間帯ごとに固定）。

タイプ内容誤答リスク対策
L1論理パズル（正直者・嘘つき / 順序 / 対応づけ）閉じた DSL（machine_spec）で全列挙して唯一解を検証 + 答えを伏せた独立 LLM 解答との一致検証
L3フェルミ推定（答えは「約〇〇（目安）」の幅で示す）独立 LLM 推定とのオーダー一致検証。断定表現を禁止

動画構成は 20 秒・4 カット（つかみ 3 秒 → 問題 7 秒 → 考える 5 秒〔1 秒 × 5 枚のカウントダウン〕→ 答え 5 秒）。詳細は方式側の仕様（batch-flow.html セクション 2.1）を参照。

Instagram プロアカウント 1 件（1 セット 1 アカウント）。15-7 で新規開設し、Secret 登録とトークン実働確認まで済んでいる。

投稿はリール + ストーリーズの 2 本立て（batch_sets.stories_enabled=1）。リール投稿が成功した後、同一 MP4 を同一実行内で media_type=STORIES として連続投稿する（キャプションなし。batch-flow.html セクション 3.3）。

3. スケジュール（投稿頻度）

1 日 3 回（朝 7:30 / 昼 12:30 / 夜 21:00 JST 目安）（15-4 決定）。Scheduler の追加と時刻の最終確定は 15-15 で行う。

どのスロットとして生成するかは実行時刻（SCHEDULED_AT の JST 時）から決定的に解決する。parameters.slots の from_jst_hour の境界は以下（早朝の巻き戻しを含む解決規則は方式側の実装による）。

4. プロンプトの作り方

固定文言方式。prompt_configs.prompt_text にはこのセットのテーマ・世界観と題材の条件だけを書き、出力フィールドの必須・文字数・L1 DSL の書式・禁止事項・イラスト生成プロンプトはコード側（方式）が固定で持つ（batch-flow.html セクション 2.1）。DB 側とコード側で同じことを二重に書かない。

15-13 で設計した登録予定の文言（登録は 15-14）。

社会人向けロジカルトレーニング「脳みそコーチのロジトレ」。世界観は「毎日3分の頭の体操ジム」。
ヘッドバンドとホイッスルを着けた脳のマスコット「脳みそコーチ」が進行役として出題する。

【視聴者】
・日本の社会人（20〜40代）。専門知識ゼロ・紙とペンなしで解けること。

【題材】
・日本の社会人の日常（通勤・オフィス・会議・コンビニ・自炊・週末の家事など）を舞台にする。
・実在の企業名・商品名・人名・作品名・時事の出来事は使わない。人物は A・B・C など無色の呼び方にする。
・図や表を見ないと解けない問題にしない。頭の中だけで追える情報量にする。

【question】
・声に出して10秒で読める長さ。解くのに必要な条件をすべて問題文に書き切る。
・曖昧語（たぶん・一般に・など）を使わず、答えが一意に決まる書き方にする。

【L3（フェルミ推定）のとき】
・身近な数量の「規模」を推し量る問題にする（例: 〜は日本全国で約何台か / 1年で約何回か）。
・公式・物理定数・換算値を問題文で与えて計算させる問題にしない。日常の観察から分解して概算できる問いにする。

【hook】
・今日の一問への短い呼びかけ。答え・解法のヒントは出さない。

【explanation】
・考え方の筋道を一本だけ、順を追って示す。L3 は使った数値と「○○×○○」の式の形を必ず含める。

【coach_comment】
・脳みそコーチのひとこと。体育会系だが威圧しない、明るく前向きな励まし。

【tags】
・日本語の短い語（例: 論理クイズ / 推定力 / 朝の一問）。記号は付けない。

【illustration_scene】
・問題の舞台になっている日本の日常風景を、簡潔な一文で描写する。
・人物を出す場合は後ろ姿か遠景までにし、顔を描き込まない。脳のマスコットは描かない。
・答えが分かってしまう物・数えられる並び・図表は描写しない。

decision: 15-13 の試し打ち（実 API・3 スロット）で確定した 4 点
  1. L3 の出題方向を明文化: 初回の試し打ちで「水 500mL を 20℃ から 80℃ へ温める…何分？」のように定数を与える計算問題が出た（フェルミ推定ではない）。プロンプトへ「規模を推し量る問題にする / 公式・定数を与えて計算させない」を追記し、「日本全国で平日の昼休みにコンビニで買われるおにぎりは 1 日約何個？」型に矯正した
  2. max_regenerations を 3 → 5: 夜（L1 / deep）の 5 要素の順序パズルは独立 LLM 検証（答えを伏せた別解答）が誤答して不合格になることがあり、4 回上限では 3 回に 1 回ほど再生成を使い切って異常終了した。上限を 6 回（初回 + 5）にすると 3 回連続で成功。上限に達した回はフェイルラウド（誤答を出すより落とす）という方針自体は維持する
  3. 昼のパレットをライトブルーへ変更（ユーザー決定）: 15-9 の初期値では昼＝ダークネイビーで夜とほぼ同じ見た目になっていた。朝＝クリーム / 昼＝ライトブルー / 夜＝ダークネイビーの 3 段構成にして時間帯のだし分けを視覚的に成立させた（コード側 SLOT_PALETTES の noon を差し替え）
  4. 禁則処理を組版へ追加: 句読点や閉じ括弧が行頭に落ちる（「話します
    。C は…」）事象が全カットで出ていたため、行頭禁則・行末禁則を満たす位置まで分割を追い出す処理を _wrapped_lines に入れた（本セット固有ではなく方式共通の改善）
14-11 の知見の流用 fantasy-animals-1 のプロンプト設計で効いた「①構成の明示 ②毎回変える要素の明示 ③Instagram UI セーフエリア」のうち、①②は上記の題材・question 条件として文言に取り込んだ。③は本方式ではプロンプト側の指定が不要で、組版（Pillow）がセーフエリア（右 12% / 下 15%）を計算して文字とコーチを配置する。イラストは全面背景として敷かれるため、文字の見切れは構造的に発生しない。

5. キャプションの作り方

固定文言方式。caption_templates.template_text に 1 件登録する。動画内に問題・答え・解説を焼き込む仕様のため、キャプションは視聴を促す固定文 + ハッシュタグとする（fantasy-animals-1 と同じ考え方）。15-13 で設計した登録予定の文言（登録は 15-14）。

毎日3分、頭の体操。
今日のロジトレ、何秒で解けた？
答えは動画の最後にあります💡

#ロジトレ #論理クイズ #思考力トレーニング #フェルミ推定 #脳トレ #朝活 #スキマ時間 #AIart

AI 開示はハッシュタグ #AIart で行う（14-4 の決定）。ストーリーズ投稿にはキャプションを付けない（Graph API の media_type=STORIES が caption を受け付けないため。posts のストーリーズ行はキャプション系カラムが NULL のまま記録される）。

6. 音源の構成

BGM は時間帯ごとに 1 曲・計 3 曲（15-8 で調達・前処理・登録済み）。audio_assets.time_slot にスロットを持たせ、選曲は「当該スロット一致（または NULL）の中で最も古く使ったもの」を選ぶ。加えてSE 2 種（カウントダウンティック・正解チャイム）を固定ファイル名で配置し、asset_type='se' で登録している。

7. 固定アセット（脳みそコーチ 4 表情）

カットごとにコーチの表情・ポーズを切り替える。4 枚を固定アセットとして S3 に置き、方式が起動時に読み込む（LLM/画像 API は毎回呼ばない）。ファイル名はコード側で固定。

カットS3 キーポーズ
カット 1（つかみ）assets/logic-training-1/coach_hook.png力こぶを作って呼びかける
カット 2（問題）assets/logic-training-1/coach_question.png手のひらを上に向けて問題を差し出す
カット 3（考える）assets/logic-training-1/coach_think.pngこぶしをあごに当てて考え込む
カット 4（答え）assets/logic-training-1/coach_answer.png両腕を上げたガッツポーズ

ファイル仕様: RGBA の PNG（他モード・非 PNG は異常終了）。4 枚とも 900 × 1290 px の共通キャンバスで、4 ポーズ共通の倍率で拡縮したうえで下端中央そろえにしてある。組版側は COACH_BOX（300 × 430 px）へ縦横比を保って収め、セーフエリアの右下に配置する。共通キャンバス・共通倍率にしておくことで、カットが切り替わってもコーチの大きさと立ち位置が動かない。

decision: アセット制作の手順と品質検査（15-13） 15-2 で確定した「脳みそコーチ」の 1 枚（d_brain_coach.png）をリファレンスシートとして images/edits に毎回渡し、姿勢の指示だけを差し替えて 4 枚を生成した（モデルは透過対応の gpt-image-1。gpt-image-2 は透過非対応 = 15-2 の知見）。細部の揺れを抑えるため、脳の形・線の太さ・ヘッドバンド・ホイッスル・3 色構成をプロンプトで固定し、「床の影を描かない」「文字・記号を描かない」を明示している。
生成物はプログラム検査 + 目視で受け入れ判定する。プログラム検査は ①背景の透過率 15% 超 ②四隅が完全透過 ③オフホワイトの不透明画素が一定数以上の 3 点。③は 15-13 で追加した検査で、ヘッドバンドの白面まで透過に抜ける事故（明るいカットでは背景が透けて白く見えるため気づけず、夜のダークパレットで初めて破綻する）を捕まえるためのもの。目視では姿勢の破綻（指の崩れ・腕の融合）・ヘッドバンドの色化け・輪郭外のノイズ画素を確認し、不合格なら生成し直す。
作り直す場合の入力（リファレンス画像・生成プロンプト・正規化スクリプト）は plans/15-13-trial/ にある（plans/ は Git 管理外）。

8. 失敗時ポリシー

共通の失敗時ポリシー（operation.html セクション 4）に準拠する。本セット固有の注意点は以下。

  • 品質検証に通らない場合は再生成（max_regenerations=5。15-13 で 3 → 5 に改訂 = セクション 4 の parameters が正）。上限まで通らなければ異常終了させ、その回は投稿しない（誤答を出すより落とす）
  • 情景イラストの生成失敗は縮退せず異常終了（15-10 決定）。イラストが全カットのカード内ブロックに常駐する構成（15-14 の投稿前レビューで全面背景から変更）のため、欠けた状態では成立しない
  • コーチアセット・SE の欠落、スロットに対応する BGM の 0 件もフェイルラウド
  • ストーリーズ投稿の失敗はリールの success を巻き戻さない。終端状態で確定した投稿失敗は Step Functions の再実行では検知できないため、検知は ECS タスク異常終了通知が担う（batch-flow.html セクション 3.4）

9. 共通フローからの差分・特記事項

使用方式は gpt-quiz-multicut（多段生成チェーン: テキスト生成 → 検証 → 情景イラスト生成 → Pillow 組版 → ffmpeg 合成）。既存セット（gpt-image-kenburns）とは生成方式が異なるが、出力がリール用 MP4 である点は共通で、SNS 投稿バッチ側の差分はストーリーズ連続投稿のみ（15-12 で実装）。方式設計書 docs/app/generators/gpt-quiz-multicut.html は「本採用時に作成」ルールに従い 15-16 で作成する。

本セットは共通テーブルのうち quiz_items（出題の重複検査用の履歴）を使う唯一のセットである（data-model.html セクション 4）。重複検査は直近の要旨 30 件をプロンプトで除外指示し、生成後に直近 120 問との bigram Jaccard 類似度で判定する。
