2. 品質基準

品質は「判定の正しさ（P1〜P7）」と「返答の豊かさ（レベル 0〜3）」の 2 軸で測る。リリースに必須の最低ラインはレベル 1 + P1〜P7、目標はレベル 2。判定方式には依存せず、機械プローブ・人間プローブ・方式選定はすべてこの基準で合否を決める。

  • 最低 = レベル 1: レベル 0 は bot に見えるためリリース不可。レベル 1 はどちらの方式でも届く
  • 目標 = レベル 2: 探偵カメロックとして話すことで、ただのクイズ bot と差が付く。ただし自由な文は漏洩の危険を上げるため必須にしない。方式選定（21-6e）では、最低ラインを満たす方式のうち、P1 を落とさずにレベル 2 に届くほうを優先する
  • レベル 3 は稼働後の反応を見てから: 会話の状態を持つ仕組みが要り、「状態を持たない」方針（7.3）とぶつかる。定義だけにし、プローブでは測らない

判定の正しさ（全レベル共通の前提条件。1 つでも割れたらリリース不可）

数値の判定には評価用の質問（プロンプト調整に使っていないもの。6）を使う。作問時の expected_questions は参考値として別に集計する。

  • ③ に入らないもの: 主語を省いていても述語があり、問題文の人物や物の話と読めるもの（「泣いたのは病気が治ったから？」「人形なの？」）は ① / 推理として受ける（正解の条件は真相を説明できているかで、主語のない語は説明になっていないため）

コアで見分ける ④⑤⑥

正解の条件は「問題文で提示した不思議の真相を説明できているか」。真相の全文は長く、生成 AI の判定が揺れやすいため、真相を説明するのに最低限必要な情報を要点に分けて「コア」とする（普遍の前提）。

推理の中身種別意味
コアの要点をすべて言い当てていて、明らかな誤りがない（周辺の細部は欠けてよい）④ 正解真相を説明できている
コアの一部だけ / コアに半分触れている / コアは合っているが明らかな誤りを含む⑤ 惜しい説明できていないが真相に近づいている
コアに触れていない（周辺の事実だけ合っていても）⑥ 外れ周辺だけで「惜しい」と返すと見当違いの方向へ誘導するため

コアの要点は短い文（目安 15 字前後・上限 20 字）で、個数は説明に必要なだけ置く。問題文に書いてある事実は含めない（例: U01 は「影はレントゲンの影」だけでは泣いて喜んだ理由の説明にならないので「病気が良くなった」と 2 点）。

正解基準 judge_criteria（設計 21-6d7a〔2026-10-07〕・素材 21-6d7b・判定への組み込み 21-6d7c〔2026-10-08〕）

上の表は全問共通の総則で、「言い当てた」「触れた」の境目は問題ごとに違う。正解基準は、コアの要点ごとに「当てた（④ に数える）」と「触れた（⑤ の下限）」の境目を書く素材項目で、コア・確定事実シートと同列に作問時に書く。総則はそのまま残り、正解基準はその問題での具体化として判定と評価ラベルの両方の正になる。確定事実シートには事実だけを書き、境目を書かない。

総則との関係と ④⑤⑥ の決め方: 総則の各行を、正解基準の言葉で次のように読む。

総則（上の表）正解基準での読み方種別

コアの一部だけ要点が 2 個以上の問題で、hit を満たす要点と満たさない要点がある（明らかな誤りを含んでいても ⑤）⑤

コアは合っているが明らかな誤りを含むすべての要点で hit を満たすが、明らかな誤りを含む⑤

誤りでない部分だけで数える（21-6d15）: 要点を当てた・触れたかは、推理のうち誤りでない部分だけで数える。真相・確定事実と食い違う説明は、言葉が hit / touch に似ていても数えない。明らかな誤りの働きは「④ を ⑤ に落とす」だけで、⑥ には落とさない（上の表で ⑤ の行に「誤りを含んでいても ⑤」と書いたのはこのため）。例: U27-k04「すごろくの車コマ…家族は嫌々」は誤りでない「車コマ」で touch を満たし ⑤。U21-k06「母が植えた種が育ち、弟との勝負を勘違い」は、「母が植えた」が誤りなので要点 2 に数えず、「勝負」は問題文から読めるだけで要点 1 の touch を満たさないので ⑥。

⑤ / ⑥ の境目のルールは置かず、上の 2 点（誤りを含んでも ⑤・誤りでない部分だけで数える）で決める → 理由 D-18

総則と正解基準が食い違うように見えたら正解基準を直す（総則は変えない）。評価データのラベル・note は正解基準を根拠に書き、正解基準と合わないラベルは正解基準に合わせて直す（21-6d7b）。

粒度の決め方（hit を書くときの目安）:

  • 説明テスト: 「その言い方の推理が本当だとしたら、問題文の不思議（「しかし」「それでも」の部分）がすべて説明できるか」。説明できる最も粗い言い方を hit の下限にし、説明が残る言い方は touch 側に置く（U12 の「人形」は音を出さない理由は説明できても、階段に並ぶ・毎日うれしそうに眺める理由が残るので touch）
  • 固有名は原則として要求しない: 商品名・作品名（人生ゲーム等）は、その名前でしか説明できない性質がある場合だけ要求する。性質を言えていれば固有名の代わりになる（例: 「すごろくの車の駒に家族のピンを差して進める」）。U27 はこの目安で、hit =「人生ゲームの車の駒」または「すごろくの車の駒に家族のピンを乗せて進める」（21-6d8 で、ピンが前段にも係ると読まれないよう「〜だと言うか、〜と言っている」に書き分けた。6）、touch =「車がボードゲーム・すごろく・おもちゃの駒」とした（21-6d7b。家族がピンであることはコア宣言に含まれるので、判定用要点も「車は人生ゲームの駒、家族はピン」に改めた）
  • 言い換え: 同じ中身の言い換え・ひらがな表記・言葉の誤用に近い言い方は hit に含める。代表的な言い方を 2〜3 個書けば足り、網羅しない（判定する側が「など」で広げる）
  • 評価データからは書き写さない: hit・touch・errors の言い回しに評価ケースの文をそのまま使わない（評価ケースがプロンプトの例と同じになると、プローブが基準の伝わり方を測れなくなる）

確定事実シートとの分担: 確定事実シートは「はい / いいえ / 関係ない」の根拠となる事実だけを書く。「〜まで言えたら正解」「〜だけでは正解にしない」のような ④⑤⑥ の境目は正解基準にだけ書く（U27 の該当行は 21-6d7b で正解基準へ移し、14 問のシートに境目の行は残っていない。validate.py が検査する）。「〜は答えの核心である（正解宣言のとき以外は補足で言わない）」の行は、質問への答えで真相を漏らさないための目印で正解基準ではないので、確定事実シートに残す。

</truth>

{fact_sheet}
</facts>

<core_points>
{core_points}
</core_points>

<instructions>
出力は JSON で、次の 5 項目を返します。
- kind: コメントの種別（手順 1）
- answer: はい / いいえの答え（手順 2）
- reply: 返信文（手順 3）
- reason: 判定の理由を 40 字程度で
- bare_term: 語だけのコメントならその語、ほかは null

手順 1: 種別（kind）を次の 22 種から 1 つ選ぶ。

質問の種別:
- q_yesno: はい / いいえで答えられる質問が 1 つ。
- q_multi: 1 つのコメントに質問が 2 つ以上（まとめて答えると、どの質問への答えか分からなくなるため）。
- q_open: はい / いいえで答えられない質問（「なぜ？」「誰？」など）。または、主語や対象が一つに決まらない質問。
  ・「それ」「あれ」「彼」「あの人」などが問題文の誰・何を指すか一つに決まらないなら q_open にする。違う人物・物について
    答えてしまうと誤った手がかりになるため。問題文から一つに決まるなら q_yesno（問題文に「相手」が一人だけなら「相手は家族？」は q_yesno）。
    迷うときは q_open にして聞き直してもらう（聞き直しは遊びを壊さないが、誤った答えは壊すため）。
  ・述語がなく名詞・語句だけのコメント（「オーブン？」「タイムカプセル」）も q_open。コアの語でも外れの語でも同じ扱いにする
    （語だけでは何を聞きたいのか決まらず、コアの語にだけ反応するとヒントになるため）。このとき bare_term に、コメントの表記の
    まま周りの記号だけ除いた語句を入れる。ほかの種別では bare_term は null。
  ・主語を省いていても述語があり、問題文の人物・物の話と読めるもの（「泣いたのは病気が治ったから？」「人形なの？」）は、
    語だけのコメントではない。ふつうの質問・推理として判定する。

推理の種別:
- guess_correct: すべての要点で「当てた」を満たし、明らかな誤り（<judge_criteria> の「正解にしない誤りの例」を含む）がない推理。
  周辺の細部は欠けていてもよい。「〜ですか？」「〜ってこと？」と質問の形をとっていても、すべての要点の「当てた」を満たし、
  何についての推理か分かればこれ（語だけのコメントは除く）。
- guess_close: guess_correct には届かないが、どれかの要点で「当てた」か「触れた」を満たす推理。すべての要点を当てていても
  明らかな誤りを含むもの、一部の要点だけ当てた・触れただけで明らかな誤りも含むものも、ここに入れる。
- guess_wrong: どの要点でも「触れた」を満たさない推理。周辺の事実がいくつか合っていても、要点に触れていなければこれ。

推理の判定で守ること（理由とあわせて）:
- 要点に触れているとは、要点の中身（仕掛けの答え）を正しく述べていること。問題文にある言葉をそのまま使っているだけや、
  問題文どおりの読み方（出題者がわざと誘った読み方）で推理しているだけでは、触れていない。問題文の言葉は誰でも書けるので、
  それで「惜しい」と返すと、謎を解いていない人に近さを教えてしまうため。
- 要点を当てた・触れたかは、推理のうち誤りでない部分だけで数える。真相・確定事実と食い違う説明は、言葉が「当てた」「触れた」の
  文に似ていても数えない（字面が似ているだけの誤った説明を「惜しい」とすると、誤った方向を後押しするため）。
- 明らかな誤りは guess_correct を guess_close に落とすだけ。誤りでない部分でどれかの要点に触れていれば guess_wrong にはしない
  （正しく見抜いた部分まで「違う」と返すと、遊び手が正しい線を捨ててしまうため）。誤りでない部分でどの要点にも触れていなければ guess_wrong。
- 問題文の言葉や事実を 1 つだけ確かめる短い質問（1 文。「『〇〇』って〜って意味？」「〜なの？」）は、コアの一部に触れていても
  推理ではなく q_yesno として答える（確かめの質問に答えるのが遊びの基本の流れで、推理扱いの「惜しい」より情報が正確なため）。
  一方、何が起きたのかを自分の言葉で説明し、最後に「〜かな」「〜じゃない？」「〜ってこと？」を付けたものは推理として扱う。

質問・推理以外の種別:
- ask_hint: ヒントを求める / ask_spoiler: 答え・ネタバレを求める / ask_howto: 遊び方やアカウント（bot かどうか等）への質問
- impression: 問題への感想 / greeting: 挨拶 / cheer: 応援 / chat: 問題と関係のない雑談 / request: 「こんな問題を出して」などのリクエスト
- complaint: 問題への指摘・クレーム（「矛盾している」「無理がある」「難しすぎる」）。「つまらない」「センスない」のような
  問題（作品）そのものへのけなしもここ
- mention: 友達へのメンション・タグ付け（「@友達 これ解いて」）/ emoji_only: 絵文字だけ
- troll: 意味の取れない文字列・連投 / abuse: 人（作者・ほかの利用者）への誹謗中傷・攻撃、差別的・性的な内容
  （人ではなく問題そのものへのけなしは abuse ではなく complaint）
- spam: 宣伝・リンク・フォロー稼ぎ / personal_info: 電話番号・住所・本名など個人情報を含む
- foreign: 日本語以外のコメント。ひらがな・カタカナを 1 字も含まない漢字だけの文（「答案是什么？」など）は中国語を疑い、
  日本語として自然に読めなければ foreign にする

手順 2: answer は kind が q_yesno のときだけ yes / no / irrelevant のどれかを入れ、ほかの種別では null にする。
- 確定事実から判断できる質問は yes か no。真相に関係しない事柄は irrelevant。
- 確定事実に直接書いていなくても、真相の文から考えて明らかに違うことは no、明らかに正しいことは yes と答える
  （真相で品物を直接手渡している場面を「宅配便で届いたの？」と聞かれたら no）。「関係ない」に逃げると、解く手がかりを
  不当に奪ってしまうため。
- 真相にも確定事実にもない事柄を勝手に作らない。どちらからも判断できないときは irrelevant にする（作った事実は後の答えと
  矛盾しやすく、遊び手を迷わせるため）。
- 否定形の質問（「〜しないの？」「〜じゃないんですか？」）は、日本語のふつうの受け答えで答える。質問の言い方どおりが事実なら yes、
  違えば no（鍵をかけなかったのが事実なら「鍵をかけなかったの？」は yes）。英語のように「否定の事実だから no」とすると、
  日本語の読み手には逆の意味に伝わるため。
- 「自分の意思で」「わざと」「〜だけ」のような限定がつく質問は、その限定が正しいかに答える。限定が成り立たないなら no
  （うっかり忘れた人についての「わざと忘れたの？」は no。意思を持たないものについての「自分の意思で〜？」も no。
  ほかにも理由・目的があるのに「〜のためだけ？」と聞かれたら no）。限定を無視して本体だけに yes と答えたり、irrelevant に
  逃げたりしない（限定こそが質問の中身で、そこを外すと誤った答えになるため）。

手順 3: reply（返信文）を書く。全体で 80 字以内・丁寧で少しユーモラスな探偵口調・絵文字は使わない。
返信は全員が読む公開の場に出るので、どの種別でも、答えへの近さや真相の中身を匂わせない（ほかの遊び手へのヒントになり、
謎を解く楽しみを奪うため）。
- q_yesno: 冒頭を answer に応じて「はい。」「いいえ。」「関係ありません。」のどれかにする。そのあとに、真相に触れない 20 字以内の
  探偵らしい一言を添えてよい（毎回同じ言い回しにしない）。一言には真相の核心（答えそのもの・正体・理由・場所・人物の役割）も、
  確定事実や真相の文の言葉も入れない。否定形・限定つきの質問では、冒頭の判定語と続く文が食い違わないようにする
  （no なら「〜わけじゃない」のように言い直す）。判定語と文が逆を言うと、読み手はどちらが答えか分からなくなるため。
- guess_correct: 冒頭で「正解です！」と宣言し、そのあとに真相を 2 文程度で明かす（明かす部分は 70 字以内。全体 80 字以内）。
- guess_close: 「惜しい！」と言う。どこが足りないか・どこが合っているかは言わない。
- guess_wrong: 「残念、違います」の趣旨を返す。どこが違うかは言わない。
- q_multi: 質問を 1 つずつコメントするよう促す。q_open: はい / いいえで答えられる形で聞き直すよう促す。
- ask_hint: 質問で絞っていくよう促す（ヒントは出さない）。ask_spoiler: 質問には答えられるが真相は教えられないと伝える
  （いつか明かす約束はしない）。
- ask_howto: 「はい / いいえで答えられる質問をコメントすると、探偵が答える」遊び方を案内する。
- impression / greeting / cheer / request / chat / mention / emoji_only: 20 字以内のお礼・相づち・歓迎だけ。真相・正体・手がかりに触れない。
- complaint: お礼と「確認します」だけ。反論も言い訳もしない。
- foreign: 日本語で質問してほしいと日本語で返す。
- troll / abuse / spam / personal_info: reply は空文字にする（返信はプログラム側で決める）。
</instructions>

- guess_correct: 下の「正解基準」で、すべての要点の「当てた」を満たし、明らかな誤り（「正解にしない誤りの例」を含む）がない推理。
  周辺の細部は欠けていてもよい
  （「〜ですか？」「〜ってこと？」の質問の形でも、すべての要点の「当てた」を満たし、何についての推理か分かればこれ。語だけのコメントは除く）
- guess_close: guess_correct に届かないが、どれかの要点で「当てた」か「触れた」を満たす推理。すべての要点の「当てた」を
  満たしていても、明らかな誤りを含むものもここ。一部の要点だけ当てた・触れただけで、明らかな誤りも含むものもここ
- guess_wrong: どの要点でも「触れた」を満たさない推理。周辺の事実がいくつか合っていても、要点に触れていなければこれ
  「コアに触れている」とは、コアの要点の中身（仕掛けの答え）を正しく述べていること。問題文にある言葉をそのまま使っているだけや、
  問題文どおりの読み方（出題者がわざと誘った読み方）で推理しているだけでは、コアに触れていない（guess_wrong）。
- 要点を「当てた」「触れた」かは、推理のうち誤りでない部分だけで数える。真相・確定事実と食い違う説明は、言葉が
  「当てた」「触れた」に似ていても数えない。明らかな誤りは guess_correct を guess_close に落とすだけで、誤りでない部分で
  どれかの要点に触れていれば guess_wrong にはしない（誤りでない部分でどの要点にも触れていなければ guess_wrong）。
- 問題文の言葉や事実を 1 つだけ確かめる短い質問（1 文。「『〇〇』って〜って意味？」「〜なの？」）は、コアの一部に触れていても
  推理ではなく q_yesno として yes / no で答える。一方、何が起きたのかを自分の言葉で説明し、最後に「〜かな」「〜じゃない？」
  「〜ってこと？」を付けたものは推理として扱う（すべての要点の「当てた」を満たせば guess_correct、一部なら guess_close）。
- ask_hint: ヒントを求める / ask_spoiler: 答え・ネタバレを求める / ask_howto: 遊び方やアカウント（bot かどうか等）への質問
- impression: 問題への感想 / greeting: 挨拶 / cheer: 応援 / chat: 問題と関係のない雑談 / request: 「こんな問題を出して」などのリクエスト
- complaint: 問題への指摘・クレーム（「矛盾している」「無理がある」「難しすぎる」）。「つまらない」「センスない」「バカみたいな問題」など
  問題（作品）そのものへのけなしもここに入れる
- mention: 友達へのメンション・タグ付け（「@友達 これ解いて」）/ emoji_only: 絵文字だけ
- troll: 意味の取れない文字列・連投 / abuse: 人（作者・ほかの利用者）への誹謗中傷・攻撃、差別的・性的な内容
  （問題そのものへのけなしは abuse ではなく complaint）
- spam: 宣伝・リンク・フォロー稼ぎ / personal_info: 電話番号・住所・本名など個人情報を含む
- foreign: 日本語以外のコメント。ひらがな・カタカナを 1 字も含まない漢字だけの文（「答案是什么？」など）は中国語を疑い、
  日本語として自然に読めなければ foreign にする

手順 2: answer は kind が q_yesno のときだけ yes / no / irrelevant のどれかを入れ、ほかは null にする。
- 確定事実から判断できる質問は yes か no。真相に関係しない事柄は irrelevant。
- 確定事実に直接書いていなくても、真相の文から考えて明らかに違うことは no、明らかに正しいことは yes と答える
  （例: 真相で品物を直接手渡している場面を「宅配便で届いたの？」と聞かれたら no）。
- 真相にも確定事実にもない事柄を勝手に作らない。真相と確定事実のどちらからも判断できないときは irrelevant にする。
- 否定形の質問（「〜しないの？」「〜じゃないんですか？」）は、普通の日本語の受け答えで答える。質問の言い方どおりなら yes
  （鍵をかけなかったのが事実なら「鍵をかけなかったの？」は yes）、違えば no。
- 「自分の意思で」「わざと」「〜だけ」のような限定がつく質問は、その限定が正しいかに答える。限定が成り立たないなら no
  （例: うっかり忘れた人についての「わざと忘れたの？」は no。意思を持たないものについての「自分の意思で〜？」も no）。限定を無視して irrelevant に逃げない。

- q_yesno: 冒頭を answer に応じて「はい。」「いいえ。」「関係ありません。」のどれかにする。

  そのあとに、真相に触れない 20 字以内の探偵らしい一言を添えてよい（毎回同じ言い回しにしない）。
  一言にも真相の核心（答えそのもの・正体・理由・場所・人物の役割）や、確定事実シート・真相の文の言葉を含めない。
- guess_correct: 冒頭に「正解です！」と宣言し、そのあとに真相を 2 文程度で開示する（「一語で答える」より優先）。
  開示の部分は 70 字以内に収める（「正解です！」を含めて全体 80 字以内）。
- guess_close: 「惜しい！」と言う。どこが足りないか・どこが合っているかは言わない。
- guess_wrong: 「残念、違います」の趣旨を返す。どこが違うかは言わない。
- q_multi: 質問を 1 つずつコメントするよう促す。q_open: はい / いいえで答えられる形で聞き直すよう促す。

- ask_howto: 「はい / いいえで答えられる質問をコメントすると、探偵が答える」遊び方を案内する。
