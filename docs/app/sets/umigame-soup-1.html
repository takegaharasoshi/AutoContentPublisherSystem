1. テーマ

要点Instagram リールで 1 日 1 問のウミガメのスープを出し、コメントの質問に AI 出題者「探偵カメロック」が自動で答える参加型セット。コメントで遊ぶ仕組みが、事業戦略の本命経路（コメント → リーチ → Meta ボーナス）に乗りやすい。

既存 3 セットは見て終わりの放送型。本セットはコメントで遊ぶ多ターン参加型で、コメントエンゲージメント → リーチ増幅 → Meta ボーナスという事業戦略書の本命経路に構造的に乗りやすいことが企画価値（固有の収益モデルは持たない）。

  • 出題者 = アカウントそのもの: 出題者キャラ「探偵カメロック」（丸い体・前掛け・透明な黄金スープの椀と匙・虫眼鏡を持つウミガメの探偵）をアカウントの顔にし、AI の返信はアカウント名義で付く
  • 質問者キャラ: 「カメロック Jr.」（探偵の子ども。大きすぎる鹿撃ち帽・蝶ネクタイ・メモ帳）がリール内でプレイ例を演じる（将来の助手サブアカウント構想と名前を揃える。21-1 ④）
  • 効果仮説: コメント率（コメント数 / リーチ）が logic-training-1 より高く、リーチの伸び率に転化する。稼働 2 週間後の確認待ちとして、21-8 で作るセット計画書に起票する
  • 既存セットとの関係: logic-training-1 の夜スロット（とんち・水平思考）とはテーマが異なり、ストックの共用・ネタの融通はしない（カニバリを助長するため。アイデア詳細 11）
  • コールドスタート対策: リール版面にプレイ例 3 往復を焼き込み、参加ゼロでもリール単体で遊び方と面白さが伝わるようにする。固定コメント（ピン留め）と助手サブアカウントは初期版では作らない（要否は稼働 2 週間後に判断）。偽装アカウント（桜）は Meta の非真正行為規約に当たるため使わない

5. イラスト作成用プロンプト（ストック整備時・imagegen）

要点1 問 1 枚の背景を、Codex CLI の画像生成で作る。プロンプトは「画風固定行 + 情景 + 禁止事項」の 3 部構成。人物は下半分の中央に小さく置く。

本セットの生成方式 umigame-prebuilt は実行時に LLM・画像生成 API を呼ばない（事前ビルド方式）。背景イラストはストック整備時に、ストックの illustration_prompt から Codex CLI の image_gen.imagegen（codex exec）で生成する（21-2 で CLI からの自動化を実測。手作業不要）。画風固定行は全問共通の定数で、validate.py が存在を検査する。

  • 画風（C4）: 90 年代 OVA の手描きセル塗り（太い主線・エアブラシのハイライト・リムライト）。背景は中間調（月明かりと蝋燭で情景が見える明るさ）で生成し、版面のオーバーレイは薄くする（第 1 稿の暗めの単色トーンは暗すぎたため変更 = 21-2）
  • 固定の禁止事項: 文字・ロゴを入れない。真相の手がかりを描かない（問題文にある情景だけを描く。人物は問題文に出る人物 + 遠景のシルエット 1 人まで）
  • 人物の大きさと位置: 遠景の小さな全身像にし、下半分の中央（横幅の中央 20%・縦 55〜85%）にだけ置く。上半分には人物を置かず静か（空・壁・天井・窓）にし、下半分の左右 40% は景物だけにする。クローズアップ・半身は描かない（感情は表情でなく姿勢で出す）。理由は付録
  • 背景のレビュー: background_sheet.py --stills（今の文言と背景で動画の各コマを書き出す）で版面と重ねて見る
  • 寸法は 9:16（1024x1536）で生成し、ビルド時に 1080x1920 へ正規化する（方式設計書 8.1）
  • キャラクター 2 体はストック単位では生成しない（セクション 9）

要点キャプションはストックの caption に問題ごとに書き、テンプレートは {{caption}} の 1 行だけ。構成は全問共通の 4 段。

  • 遊び方の文: 「はい / いいえ / 関係ない」で答えられる質問をコメントしてね。出題者のカメロックが全部返事します。正解が出るまで何度でもどうぞ
  • ハッシュタグ: #ウミガメのスープ #水平思考 #推理クイズ #なぞなぞ #謎解き #クイズ #コメント即時返信 #AIart
  • 書かないもの: 問題番号「第 N 問」（ストックは LRU で消費され、投稿順が確定しないため。PoC の表記は本番では使わない）。問題文の要約（すぐ下の問題文と同じ話が 2 回出るように見えるため。2026-09-24 ユーザー決定）
  • AI 開示: #AIart はストック側の必須項目として validate.py で検査する（テンプレートが {{caption}} だけのため、運用設計 3 の「テンプレートに含める」ルールの担保はストック検証に移る）。ナレーションは Irodori-TTS でクレジット表記は不要（セクション 8）
  • テンプレートを {{caption}} だけにする理由: ハッシュタグの固定部を分けると、問題固有のタグを足したいときに 2 か所を見ることになり、素材 14 項目の表（セクション 4）とも食い違うため。固定尾部が必要になったらテンプレート側に足す（DDL 変更なし）

11. 失敗時ポリシー

  • 投稿側は共通フローどおり（batch-flow.html 3.2 / operation.html 4）。事前動画の取得失敗・ストック 0 件はフェイルラウド（縮退しない）。1 日 1 回のため 1 回の失敗はその日の投稿の欠落に留まる。当日リカバリの判断は共通課題（課題体系 I-019）に従う
  • スナップショット出力の失敗は投稿失敗にせず、NULL 行の確認クエリと手動再出力で回復する（10.7.2）
  • コメント側: Reply Lambda の失敗は SQS の再試行（最大 3 回）→ DLQ → アラーム。返信が遅れる・付かないことはあっても投稿には影響しない。固定文言での代わりの返信はしない
  • Webhook Lambdaは署名検証に失敗した要求を 401 で拒否し、正常受信は SQS へ入れた時点で 200 を返す（Meta の再送を招かないため、enqueue 失敗以外は 200）
  • OpenAI の長期障害: 予約同時実行数と SQS の保持期間（4 日）内なら復旧後に自動で返信が付く。それを超えた分は DLQ から手動で再駆動するか、古すぎれば破棄する（返信の鮮度を優先）
