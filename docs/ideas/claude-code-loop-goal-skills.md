## 要旨

Claude Code の「ループ」スキル・「ゴール」スキルを使いこなせば開発速度が上がるのではないか、という仮説。
単発で試すだけでなく、**本プロジェクトの開発プロセスそのものに組み込めないか**を検討したい（例: セッションを跨いで自走させる、定型作業を無人で回す、完了条件を宣言して到達まで任せる、など）。

事業コンテンツではなく開発プロセス（作業環境）の改善アイデア。同系統: [voice-input-tooling](voice-input-tooling.md)（音声入力ツール導入）。

## 前提条件・再検討トリガー

- 【要確認】「ループ」スキル = `/loop`（プロンプトやスラッシュコマンドを一定間隔 or 自己ペースで繰り返し実行する Claude Code 標準スキル）と思われる。「ゴール」スキルが具体的に何を指すかは未特定（`/schedule` のことか、別途聞いた機能か）。壁打ちの最初に対象を確定させる
- 【組み込み先の候補】週次のストック補充（quiz-stock-replenish / ranking-stock-replenish）、CodePipeline 完走待ちのポーリング、稼働確認待ちなど「待ち」と「定型反復」が混じる作業 — 具体化は壁打ちで
- 【評価軸】速度向上と引き換えに増えるトークン消費・レビュー負荷をどう見るか（本プロジェクトは Codex 委譲でトークン節約を方針としている）
