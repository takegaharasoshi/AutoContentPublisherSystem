1. 一言で

Claude Code のトークン消費を下げるため、Codex を「Claude から MCP 経由で呼ばれる実装ワーカー」に加えて「ユーザーが codex を起動して単独で作業を回すエージェント」としても使えるようにする。対象は設計書・コード品質への影響が小さい定型作業（logic-training-1 の週次補充、アイデアの捕捉・壁打ち、課題の棚卸し）。障壁は 2 つ — AGENTS.md が docs/ 配下・CLAUDE.md・.claude/ の変更を禁止していること（記録の書き戻しができない）と、運用手順が .claude/skills/ にあって Codex から起動できないこと。

4. 実現手段の論点 3 つ

4.1 MCP ワーカー時との両立（最大のリスク）

AGENTS.md は Claude から MCP 経由で呼ぶときも読まれる。素朴に緩めると「委譲した実装タスクで Codex が docs を書き換える」事故が起きる。対策は 2 段構え。

  • AGENTS.md 側: docs への書き込みは「スキル起動時（$idea $issue $quiz-stock-replenish）と、指示文で明示された場合のみ」の条件付きにする。MCP ワーカー時の「commit は指示された場合のみ」は維持
  • CLAUDE.md の Codex 連携節: 委譲指示文に「docs/ は触らない」を含める（プロンプトが AGENTS.md より優先される仕様を使う）

4.2 git ルールの移植

直接セッションでスキルの終了規律（コミット + push）まで完走させるには、日本語メッセージ・pull --rebase・その場で push・ファイル指定 add・他セッションの変更を巻き込まない、が Codex にも要る。CLAUDE.md との二重記述を避け、AGENTS.md からは「Git 運用ルールは CLAUDE.md の当該節に従う」と参照で逃がす。

4.3 /goal の代替

Codex 側で同じ完了条件を強制する仕組みはない。各 SKILL.md に「エージェント別の差分」節を 1 つ設け、Claude = /goal 起動、Codex = 同じ完了条件文を update_plan の項目として立てて証跡（在庫クエリ・検証・更新行数の出力）を貼る、と書き分ける。骨格（G1〜G3 の切り方・証跡を貼る規律）は共通のまま。
