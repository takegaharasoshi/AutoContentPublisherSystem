## 要旨

スマホから設計書 HTML を日常的に読むための表示改善。最優先は、表が画面幅に押し込まれて列内の折り返しが増え、極端に縦長になる問題の解消。2026-09-20 の壁打ちで以下の範囲を合意した（採用・実装着手の判断は未了）。

- **一般の表**（計画体系の各種表・事業戦略の各種表など）: 読みやすい列幅を保ち、収まらない分は表の中だけ横スクロールする。短い表は画面幅に収める。文字の縮小・内容の省略で解決しない。
- **課題一覧・アイデア一覧**: スマホでは項目名付きのカード形式、PC では表形式を維持する。判断に必要な情報を常に表示し、補足情報をカード内でタップして展開する。
  - 課題は ID・課題の内容・状態・対応方針・トリガーを常時表示し、対象パス・発生履歴などを折りたたむ。
  - アイデアはタイトル・状態・要旨・待機条件を常時表示し、更新日・補足情報などを折りたたむ（存在する項目のみ）。
  - 初期対応は既存の内容をそのまま使う。独立した短い課題名の新設や説明文の要約・書き直しは必須にしない。長い本文そのものを短くする効果までは期待せず、細い列での折り返しと補足情報の常時表示を減らす。
- **対象外**: 計画書そのものの構成・見せ方の再設計（ステップの縦並び化を含む）。PC でも見づらいという既存の課題として [I-036](../issues/index.html#I-036) に分離した。計画体系・計画書内の一般の表に共通の列幅対策を適用することは今回の範囲に含む。
- 閲覧経路（WSL の HTTP サーバー + tailscale serve）の変更は対象外。

現状確認（2026-09-20、ソース確認のみ）: アーカイブを除く HTML は 44 本で、全て共通 CSS と viewport meta を参照。共通 CSS には画面幅のブレークポイントがなく、表のラッパーには横スクロール指定があるが、列幅確保は別途必要。実機での表示確認は未実施。

## 前提条件・再検討トリガー

- 実装は共通 CSS と対象 HTML に及ぶ開発レーン作業。アイデアレーンでは検討記録・転記下書きまで。
- 未決: 対象画面幅と代表ページ、表の列幅の決め方、実機での受け入れ基準。先頭列固定は候補であり未決。
- 余白・図・目次の変更は今回の必須範囲として合意していない。
- ステータスは醸成中。スマホ対応の採用判断・転記下書きは次の壁打ちで整理する。

## 壁打ち記録

### 2026-09-20 — 表の縦長化対策と計画書改善の分離

- 論点: スマホで最も困るのは、各所の表が狭い列に折り返されて極端に縦長になること。計画体系・事業戦略の表が具体例。
- 判断: 一般の表は列幅確保 + 表内横スクロール、課題・アイデア一覧はスマホでカード表示とする方向に合意。
- スコープ変更: 当初提案した計画のステップ表示の再構成は、PC でも見づらいという問題と合わせて別課題 I-036 に分離。ユーザーの明示指示により今回のスマホ対応から除外。計画書内を含む一般の表の共通対策は残す。
- 積み残し: 表示幅・代表ページ・カードの項目順・受け入れ基準、採用判断と開発レーン向け転記下書き。
- 着地: 醸成中。課題側は起票のみ行い、この場では壁打ちしない。


### 2026-09-20 — カード内の補足情報の折りたたみ

- 判断: 一覧で判断する情報は常時表示し、対象パス・発生履歴・更新日などはカード内で展開する案にユーザーが同意。
- 初期スコープ: 既存項目・既存文面を使い、短い課題名の独立管理や新規要約の作成は要求しない。
- 次の検討用たたき台（未合意）: 幅 360 / 390 / 430 CSS px と PC 幅 1280 CSS px で、計画体系・事業戦略・課題一覧・アイデア一覧を代表ページとして確認する。ページ全体は横にはみ出さず、一般の表だけ横スクロールし、カードの主要項目は展開せず読めることを確認する。実機でも横スクロールと開閉を試す。先頭列固定は初期必須にせず、列幅を確保した試作で必要性を判断する。
- 着地: 醸成中。表示方式は合意、受け入れ基準と採用判断は未了。I-036 の分離を維持。
