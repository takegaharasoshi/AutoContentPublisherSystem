## 要旨

当たりの兆しが出たセットを Instagram 以外のプラットフォームへ展開し、リーチを増幅するアイデア。方針の正は[事業戦略書セクション 5](../strategy/business-strategy.html#platform)（TikTok を第一候補〔動画資産をそのまま転用できる〕、X は当面見送り〔API 有料化が予算方針と不整合〕、展開の判断基準は「勝負セットで M2 到達が目安」）。

2026-07-23 の壁打ちで開発計画の「Phase 17: プラットフォーム展開」として起票され、2026-08-10 に第 3 セット構築を Phase 17 として優先するユーザー決定で「Phase XX」（着手判断時に採番）へ退避していた。2026-09-03 の開発計画の整理で、「着手するかどうか・いつか」が未決のまま計画書に居座るのは計画ではなくアイデアであるとして、本体系へ移管した（開発計画にはフェーズとして残さない）。

前提として「同一セットの投稿を複数プラットフォームへ展開する構造（セット : アカウント = 1 : N）」は設計済み（[A-1 壁打ち記録セクション 2](../app/requirements-notes.html#set)）。2 つ目のプラットフォーム追加時に batch-flow.html セクション 3 の Instagram 固有部分をどう分冊・共通化するかは開発計画の設計課題リスト（2026-07-15 の項）にある。

## 前提条件・再検討トリガー

- **再検討トリガー**: 勝負セット logic-training-1 で KPI M2 到達の目安（フォロワー・リーチの水準は事業戦略書 4.1）。16-5（2026-09-02）時点ではフォロワー 19 で未達。月次 KPI 転記（運用設計 6.3）のたびに条件列を確認する
- **再開時に調べること**: TikTok Content Posting API のアプリ審査（Direct Post の審査要件・非公開投稿制限・審査期間）、動画の尺・形式の互換性（logic-training-1 は 16 秒 3 カット、pref-ranking-1 は 30 秒）、キャプション・ハッシュタグの流儀の違い
- **前提**: 1 セット : N アカウントの設計は済み（実装は Instagram 1 アカウント分のみ）。投稿バッチのプラットフォーム別分冊（設計課題リスト 2026-07-15）は着手時に確定する
- **作らないもの（現時点）**: X への展開（事業戦略書 5 で当面見送り）。当たりが出る前の配信面の拡大（優先順位の考え方: 配信面の数より当たりコンテンツの発見が先）
- **収益との接続**: 展開は増幅器であり、収益化経路そのもの（Meta ボーナス）は Instagram にある。TikTok 側の収益経路（Creator Rewards 等）の要件は再開時に事業戦略書へ追記する
