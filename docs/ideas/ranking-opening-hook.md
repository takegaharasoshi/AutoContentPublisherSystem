## 要旨

pref-ranking-1 の 30 秒版動画は、実測で **0.00〜5.00 秒が実質完全な静止画**（`intro` 89f + `teaser` 61f = 150f）。
地図ズームはこの区間 1.04 固定、背景 ken-burns は 900f で 1.0→1.07 と知覚できず、地図に動きが出るのは 5.00 秒（5 位スピン開始）、
最初の「確定」は 6.00 秒（停止フラッシュ）。17-4a で版面の情報（タイトル帯・地図・全国平均プレート・煽り吹き出し）は
0 秒から出す判断が入っているため、課題は「情報がない」ではなく **「情報はあるが動きがゼロ」**。
ミュート視聴者が冒頭を静止画と判定してスキップしている、というのが仮説。

**対策（採用）= A + B の同時投入**。
- **A. 予熱スピン**: `intro`・`teaser` 区間でも地図のルーレットを回す。ただし本番と同速では
  タイトル・全国平均プレート・煽り文の可読性を殺し、5.00 秒の変化点も消えるため、**遅く淡い点滅から始めて
  `teaser` 終わりに向けて加速し、5.00 秒の本番スピンで最高速に到達させる**。
- **B. `teaser` の視覚化**: 煽り吹き出しにモーション（ポップイン・「？」の脈動等）を与え、
  ミュートでも「予想しろ」という参加要求が届くようにする。A が「動きの欠如」を埋めるのに対し、B は
  「17-3 で `teaser` を全ネタ必須にした狙いがミュート勢に届いていない」という別の穴を埋める。

在庫は**全本作り直す**（ユーザー判断）。レーンは**セットレーン**（`content/<set>/` 配下 + セット専用方式設計書 + セット計画書で完結）。

## 前提条件・再検討トリガー

- 実装は `content/video-build/pref-ranking-1/remotion/` 配下で完結する見込み。A は `stageAt` の
  `frame < rounds[5].start` 分岐（現在 `lit=null` を返す）と `spinTicks` の間隔式に予熱区間を足す改修。
  B は煽り吹き出しコンポーネントの改修。タイムライン定数（`scripts/build_timeline.py` の `DURATION_SPECS`）は**変えない**
  — 総尺・シーン配分には手を入れず、既存区間に動きを足すだけにする
- コストの本体は**未使用在庫の再ビルド**（2026-08-28 時点で 28 件）+ S3・DB の差し替え。
  BGM 1 曲運用のミュート検知時と同じ「在庫全本の再ビルド」オペレーション（セット別設計書セクション 6 の decision）に相当する
- **変更日をセット記録に必ず残す**。16-5 効果検証は「2026-08-08 以降の投稿を母集団に絶対水準と改善傾向を見る」設計
  （16-11 で前後比較は放棄済み）なので改善の投入自体は矛盾しないが、変更日が分からないと推移の解釈ができなくなる
- 効果の判定材料: `reels_skip_rate`（Graph API 取得可）と視聴維持カーブ（アプリ画面の目視のみ。16-6 の調査結果）

## 壁打ち記録

### 2026-08-28

**1 回の壁打ちで採用まで着地した。**

- **現状の実測で仮説を裏付けた**: 30 秒版の 0.00〜5.00 秒は動くものが何もない（`mapZoomAt` はこの区間 1.04 固定、
  `Backdrop` の ken-burns は 1 秒あたり 0.23% で知覚不能）。体感 4 秒という指摘に対し、実際は**動きまで 5.0 秒・確定まで 6.0 秒**。
  17-4a の「冒頭が空の版面はスキップされる」判断で情報は 0 秒から出ているため、残っていた穴は動きだけ、と論点を絞り込んだ
- **前提の検証手段を確認した**: 視聴維持カーブはアプリ画面で目視可能（16-6）で、ユーザーが実際に確認できることを確認。
  `reels_skip_rate` は API 取得可
- **ユーザー案（冒頭からルーレットを光らせる）は採用したが、素朴な実装は 2 つ問題があると指摘した**:
  ① 5 秒間フル点滅はミュート勢に読ませたいタイトル・全国平均プレート・煽り文の可読性と競合する
  ② 5 位スピン開始（5.0 秒）が変化点でなくなり「確定」の特別感が薄れる。
  → **加速する予熱スピン**（遅く淡く始めて本番スピンで最高速）に修正して両方を回避する形で採用
- **B（`teaser` の視覚化）を対案として追加し、ユーザー判断で A と同時投入**。理由は埋める穴が別（A = 動きの欠如、
  B = 参加要求がミュート勢に届いていない）で、どちらもセットレーンで完結し 1 回の再ビルドに相乗りできるため
- **却下した案**: 冒頭を削って 5 位発表を前倒しする案は、17-4d の実測で発話密度 79%・話速が設計上限 1.2 に到達済み・
  尺配分の余地も使い切っているため成立しない。削るなら `teaser` を捨てることになり、17-3 の判断の巻き戻しになる
- **レーン判定**: `docs/plans/index.html` の判定表で `content/<set>/` 配下（Remotion コンポジション含む）+ セット専用方式設計書 +
  セット計画書は**セットレーン**、用途例に「動画の演出・尺・構成のセット内改修」が明記されている。開発レーンの枠を消費しない
- **積み残し**: ユーザーが見た視聴維持カーブの読み（冒頭で崖になっているか、崖の位置は何秒か）を証跡として記録できていない。
  実装前に確認できれば、予熱スピンの加速カーブ設計（どこを一番強くするか）の根拠になる
