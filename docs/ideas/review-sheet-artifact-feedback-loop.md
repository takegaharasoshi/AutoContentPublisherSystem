## 要旨

レビューを効率化する案。今は HTML で作っているレビューシートを、Claude Code の Artifact でフォームやボタン付きのページとしても配信する。
レビュアーがそのページでコメントを書いて送信すると、裏で動くルーティンが送信を検知し、コメントのとおりに修正を進める。
レビューの受け渡し（ローカル HTML を読む → 会話に書き写す → 修正させる）を、フォーム送信 1 回に縮めるのが狙い。

## 前提条件・再検討トリガー

- 検知の手段を確かめる。候補は Artifact の共有 DB（ページのフォームから書き込み、`ArtifactData` で読む）、Artifact のコメント監視（`ArtifactComments`）、定期実行のルーティン（`/schedule` のクラウド実行、またはローカルの `/loop`）
- 修正を誰がどこで行うかを決める。クラウドのルーティンがリポジトリを直接触ってよいのか、ローカルのセッションへ渡すのか。並行作業ルールやレーンとの整合も要る
- 対象にするレビューシートの範囲を決める（ストック文言のレビュー・作問の人間ゲートなど）

## 原文メモ

新しいアイデアです。レビューの効率化について検討しています。

Claude Code の Artifacts という機能を使えば簡単なウェブページを作成できることが分かり、そのページにはフォームやボタンなども設置可能だと確認できました。

現状は HTML で作っているレビューシートを、フォームやボタン付きの形で Artifacts にも配信します。そして、そのフォーム上でコメントをつけて送信すると、裏でルーティンが動いて送信を検知し、コメントの通りに修正していく、というようなレビュー効率化のフローを考えています。
