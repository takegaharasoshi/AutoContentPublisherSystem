## 要旨

umigame-soup-1（探偵カメロック）のコメント自動返信を継続的に改善できるよう、1 コメントごとに「受信・判定・返信」の全記録を残し、夜間に Aurora へ蓄積する。現設計（umigame-soup-1.html セクション 10）は CloudWatch Logs（90 日）しか残らず、履歴の計画がない。
- **2 段構え**: ① 21-6c の実装で Reply Lambda が 1 コメント 1 レコード（JSON）を S3 に書く（リリース前・後付けすると稼働初日からの記録が欠けるため）。② リリース後に夜間バッチで S3 → Aurora に取り込み、取り込んだ S3 オブジェクトは消す
- **記録項目**: コメント ID・親コメント ID・media_id・問題 ID・コメント者のアプリスコープ ID（username は持たない）・本文・Meta 側作成時刻 / Webhook 受信時刻 / 判定時刻 / 返信時刻・判定ラベル・判定理由の短文・返信文・返信 ID・モデル名・プロンプト / 確定事実シートのバージョン・エラー
- **置き場**: CloudWatch Logs ではなく S3（90 日で消えない・キー = comment_id で取り込みが冪等・再処理できる・コストは 1 日 1 万件でも月 2 ドル弱で CloudWatch より安い）。運用監視のログは従来どおり CloudWatch
- **夜間バッチ**: insights-batch の 06:00 実行に相乗りし、Aurora の起動回数を増やさない
- **改善ループ**: 誤判定を拾う → 確定事実シート / プロンプトを直す → そのコメントを回帰プローブに追加。最初の見る仕組みは SQL ビュー 1 本 + 週 1 回の目視（NO_REPLY と食い下がりスレッド）。振り返りのスキル化は後回し
- 関連: [ウミガメのスープ参加型アカウント](umigame-soup-set.md)

## 原文メモ

新しいアイデアです。

「ウミガメのスープ」のコメント返信機能について、継続的に改善活動が行える状態にしたいと考えています。

現状はただコメントを返すだけの状態かと思いますが、改善を継続的に行うためには、以下のような情報を記録しておく必要があると考えています：
• 何時何分何秒にどういうコメントが来て、何時何分何秒にどう判断して何とコメントを返信したのか
• コメントの流れや、コメントしてきた人のユーザーIDなど

ただ現在の構成だと、Aurora のデータベースが止まっている状態で、S3 などを参照してコメントだけオンラインで返す仕様になっているため、溜めておきたい情報をそのまま Aurora に残しておくことはできません。

そこで例えばですが、CloudWatch Logs などに溜めておきたい情報を吐き出すようにしておき、後から1日1回、情報を収集・整理・記録する夜間バッチなどを動かして Aurora に蓄える、といった機能があればいいのかなと考えております。

アイデアについては以上です。
