## 要旨（対応方針の現在形）

整理された表示方針は [plans-readability.html](plans-readability.html)、開発計画全体の PoC は [development-plan-poc.html](development-plan-poc.html) を参照。

## 選択肢と判断

- **採用（ユーザー指定）**: ① 何をするか = 成果物を短く説明 ② 完了条件 = 条件ごとの箇条書き ③ 人が確認すること・止まる場所 = 独立した項目として表示 ④ 実装の細部・背景 = 折りたたむ。
- **採用（ユーザー追加）**: ⑤ 作業記録 = 実装の細部・背景から独立した折りたたみ項目。開発中は計画書に保持でき、計画整理時に記録ファイルへ移す。
- **採用（追加提案へのユーザー同意）**: 状態・完了日・結果の要点は折りたたみの外に残す。移行後の作業記録欄は記録ファイルへのリンクに置き換え、詳細を二重管理しない。
- **不採用**: 全項目の常時展開。ユーザーは実装の細部・背景の折りたたみを選択した。
- **不採用**: 作業記録を即時にすべて計画書から排除する運用。ユーザーは整理前の記録を計画書に置くことを許容している。
- **採用（追加提案へのユーザー同意）**: 着手条件と重要な制約は常時表示する。作業記録の見出しに短い要点を付け、記録内の方針変更は概要・条件にも反映する。既存の長いステップで見本を作り、全体への適用前に確認する。
- **PoC の追加整理**: ページ内リンク、現在地・次の候補と補足、進め方の方針、更新履歴をページから外す。完了済みステップはフェーズ内で進行中ステップより上に置き、閉じた状態にする。削除の影響と必要な参照修正は詳細 HTML に整理。
- **本適用への提案**: 共通様式・テンプレート・既存スキルの更新手順・docs_check.py の構造検査を組み合わせる。仕組みの実装はまだ行っていない。
- **次の判断**: 開発計画・各セット計画書にどこまで適用するか、既存の表・箇条書きをどう揃えるか。必要な実行条件は削除せず、表示整理と記録の移行を区別する。共通ルールに反映する際は、完了時に詳細を記録へ移す既存の記述と、今回の整理時に移す運用との整合も取る。

### 2026-09-21（方針の整理）

- ユーザーが第一案の 4 項目を採用し、作業記録を独立した折りたたみ項目にする方針を追加した。同じステップの可読性に対する対策なので I-036 にまとめる。
