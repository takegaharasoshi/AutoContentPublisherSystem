インサイト収集（配信面の機能 ②）

現行版 最終更新: 2026-10-18（Phase 30-3b で新設） 1 段上: 基本設計（全体）3 章 配信面の 5 系統

要約

インサイト収集は、投稿した動画がどれだけ見られ、反応されたかを Instagram から集めて DB に積み上げる機能である。1 日 2 回、セットごとに、直近の投稿の数値とアカウント全体の日次の数値を取り、あわせて umigame のコメント記録（コメント自動返信が S3 に置いたもの）を DB に取り込む。集めた数値は KPI のビューを通して月次の振り返りに使う。

図 1 は 1 回の収集で何を読み、どこへ書くかを表す。上が起動の流れ、下の 3 本の矢印が取り込み先。

項目要点
目的投稿とアカウントの反応の数値を、あとで比べられる形で DB に残す
きっかけEventBridge Scheduler（毎日 06:00・18:00。セットごとに 1 本ずつ）
入力Instagram Graph API のインサイト、DB の posts（直近 14 日）、S3 のコメント記録
出力post_insights・account_insights_daily・umigame_comment_logs
主な判断投稿の数値は上書きせず積み増す → 理由 D-01 / コメント記録の取り込みをこの機能に相乗りさせる → 理由 D-02

1. きっかけ

収集は時刻だけで動く。セットごとに朝と夕方の 2 本のスケジュール（acps-prod-insights-collection-{set_code}-{morning|evening}）があり、いずれも Asia/Tokyo の 06:00 と 18:00 に、セットコード・予定時刻・さかのぼる日数（14 日）を SFN に渡す。対象は稼働中の 3 セット（logic-training-1・pref-ranking-1・umigame-soup-1）。

2. 入力と出力

1 回の収集は 3 つの仕事からなる。次の表は、仕事ごとに何を読み、どこへ書くか。

仕事読む書く
投稿の数値posts（直近 14 日の投稿）・Instagram Graph API の投稿インサイト（再生数・リーチ・いいね・保存・シェア・視聴時間・スキップ率など）post_insights（収集のたびに 1 行ずつ追記）
アカウントの日次Instagram Graph API のアカウントインサイトaccount_insights_daily（前日までの日ごとの値。欠けた日はさかのぼって埋め、遅れて確定する値は取り直す）
コメント記録の取り込みS3 comment-log/{set_code}/dt={UTC 日付}/（直近数日分の日付フォルダ）umigame_comment_logs（同じコメントは 1 行だけ。保持期限を過ぎた行は削除）

コメント記録の取り込みは 3 セットすべての実行で走るが、記録があるのは umigame-soup-1 だけ。

3. 流れ

図 2 は、1 回の起動で 3 つの仕事がどの順で進むかを表す。どの仕事も、途中で 1 件失敗しても残りを続け、失敗の件数を実行ログに残す。

判断の記録

本文の「→ 理由 D-xx」から飛んでくる先。

D-01 投稿の数値は上書きせず、収集のたびに積み増す

決めたこと
post_insights は収集のたびに 1 行ずつ追記し、同じ回の再実行では増えないようにする
理由
投稿からの経過時間ごとの伸びを、あとで比べられるようにするため（KPI ビューは投稿から 72 時間の値で比べる）
日付・出典
Phase 16（インサイト収集バッチ）。バッチ処理フロー

D-02 コメント記録の取り込みをインサイト収集に相乗りさせる

決めたこと
コメント自動返信が S3 に置いた記録を、06:00 / 18:00 の収集の最後に DB へ取り込む
理由
コメント返信を Aurora が止まっていても動くようにしつつ、Aurora を起こす回数を増やさないため
日付・出典
2026-10（Phase 21-7b）。database/V016__umigame_comment_logs.sql
