logic-training-1 の生産（なぞなぞ・とんち）

現行版 最終更新: 2026-10-18（Phase 30-3c で新設。30-5 で「さらに詳しく」を生産の詳細設計へ向け、3 章 レビューのやり方を追加） 1 段上: 生産ライン（共通）。ここには共通との違いだけを書く

要約

logic-training-1 は、脳みそコーチが出題する頭の体操のリールを、朝と夜の 1 日 2 回投稿するセットである。生産では、問題（なぞなぞ・とんち・水平思考）を Web で裏を取りながら集め、候補を多めに出して人が直感で選び、完成稿・挿絵・動画まで作る。生産ライン（共通）の骨組みに沿い、3 つの関所をすべて持つ。

図 1 はこのセットの工程を、補充スキルのゴール（G1a〜G3）の単位で表す。共通との違いは、DB への投入が動画のビルドより前（G2 の最初）にあることと、人の判断から外した理由を後日の振り返りで扱うこと。

作るもの朝 = なぞなぞ、夜 = とんち・水平思考の 1 問 1 本のリール（昼のフェルミ推定は停止中 → 理由 D-01）

音ナレーションなし。BGM（時間帯に合わせて選ぶ）と効果音

1. 何を作り、素材をどう集めるか

このセットの素材は「誰が作ったか分からないほど広く出回った」問題で、問題文をそのまま写さずに書き直して使う。

2. 共通との違い

生産ライン（共通）1 章の骨組みと比べたときの、このセットの違い。

  • 投入がビルドより前: 完成稿を承認したら G2 の最初にローカル DB と Aurora の両方へ投入し、その後に挿絵を生成して動画をビルドする。配置（G3）では publish.py が S3 とローカル DB を更新し、Aurora には動画キーの更新 SQL を別に適用する
  • 振り返りのループ: 選別で NG・保留になった候補と完成稿で差し戻した候補は、週次補充とは別に quiz-review-learn で振り返る。人が理由を言葉にし、OK になれば候補へ戻し、合意した共通ルールだけを補充スキルの作問基準へ反映する
  • 挿絵: 問題ごとに挿絵を 1 枚生成する（Claude Code では Codex に生成を任せ、Codex の直接セッションでは自分で生成する）

このセットの人の関所は 3 つで、どれもユーザーが判断し、AI は判断しない。表 1 は、3 つの関所がどのゴールの後に来て、どこで何を見て、どう返すかを表す。関所の考え方（AI が先に一次スクリーニングする・動画は全数を見る）は生産ライン（共通）5 章。

関所いつ場所見るもの返し方

3.1 ① 候補の選別（チャット）

完成稿を書く前に、問題の筋だけを見て反射的に選ぶ関所。ここでの OK は「仕上げてよい」の意味で、投入の承認ではない。

AI が出すもの: スロット（朝・夜）ごとに、1 候補を 3 行（候補 ID と問題文 / 答え / 図の内容）で並べた一覧を 1 通で出す。出典の確認・既出との照合・答えの成立は AI が済ませてあり、一覧には載せない（候補ファイルの記録で開ける）。

例:

【朝・候補選別 14 件】各候補に OK / NG / 保留 を返してください(理由は不要。未判定はそのまま残ります)
m01 問題文: 黒板の式に線を 1 本足して正しい式にする
    答え: + に斜線で 4(545+5=550)  図: 黒板の式
m02 問題文: …
    答え: …  図: なし
…

ユーザーの返し方: 候補 ID を OK / NG / 保留に振り分けて返す。1 行でよい。

例:

OK: m01 m03 m05 m07 m10 / NG: m02 m06 m08 m09 m12 m13 / 保留: m04 m11 m14
  • 理由は書かなくてよい。書いた理由はそのまま記録され、書かなかった理由を AI が推測で埋めることはない
  • 迷ったら保留でよい。返さなかった候補は「未レビュー」のまま残る（NG にはならない）
  • AI はその場で NG の理由を尋ねたり、直し方を議論したりしない（理由は後日の振り返り quiz-review-learn で扱う）

返した後: AI が判定を候補ファイルに記録し、集計（tally.py）の出力を貼って「G1b へ進める」か「追加 朝 x / 夜 y」を宣言する。OK が朝・夜どちらかでも目標に足りなければ、足りない数の 2 倍の候補を追加で作り、同じ形でもう一度選別する。目標を超えた OK は候補のまま次回へ持ち越す。

3.2 ② 完成稿のレビュー（チャット・1 問ずつ）

選んだ候補を全項目まで仕上げた完成稿を、1 問ずつ確かめる関所。ここでの承認が投入の承認で、誤答を止める唯一の関所でもある。

AI が出すもの: 1 通に 1 問。機械検証（文字数・答えの検算・投入 SQL の生成）を通した後で出す。

  • 項目は日本語の名前で、表示される場所を添える: つかみ（キャプション 1 行目）・ヒント（カット 3 の吹き出し）・問題文（全カット）・答え（キャプション）・解説（キャプション）・コーチの一言（キャプションの末尾）・タグ（記録用）・出題要旨（記録用・重複の管理）・イラストの情景（問題文の下の絵の生成指示）・出典メモ
  • AI が気づいた懸念（答えが見えてしまう・既存の問題と重なる・別の答えが成り立つ）は、聞かれる前に書いて代案を添える
  • なぞなぞ・とんちの想定の答えは機械で確かめられないので、人の目が唯一の確認だと明記する

例:

【朝 3/7】A47（候補 m05）
つかみ（キャプション 1 行目）: …
ヒント（カット 3 の吹き出し）: …
問題文（全カット）: …
答え（キャプション）: … / 解説（キャプション）: …
コーチの一言（キャプション末尾）: …
タグ（記録用）: … / 出題要旨（記録用）: …
イラストの情景（問題文の下の絵）: …
出典メモ: …
気になる点: 「…」は答えの一部が問題文に見えます。代案: …

ユーザーの返し方: 次のどれかを返す。

  • 承認（「OK」）: その問題を確定し、次の問題へ進む
  • 修正の指示: 直す項目と直し方を書く（AI の代案を選ぶだけでもよい）。「他の問題も同じように」と書けば、AI が当てはまる問題を挙げて一括で直し、直した先を示す
  • NG（差し替え）: その問題をやめる。完成稿を粘って書き直さず、候補に戻す

返した後: 修正は単一ソース（stock_items.py）に反映し、機械検証を回し直してから同じ問題を出し直す。承認済みの問題を AI が勝手に変えることはない。NG の問題は候補へ差し戻し（完成稿 NG）、余っている候補 OK があれば代わりに仕上げ、なければ ① の追加に戻る。全問を承認したら G2（投入〜ビルド）へ進む。見る観点は誤答・表現の独自性・既存との重複・書式の 4 つ（生産の詳細設計 2.5）。

3.3 ③ 動画の全数レビュー（レビューシート）

ビルドした動画を全部見て、S3 に置くものを決める関所。レビューシートを開いて見て、結果をチャットで返す。

AI が出すもの: レビューシート content/video-build/logic-training-1/work/review.html（review_sheet.py が作る。2 ページ目以降へはシート上部のページ送りから移れる）。1 ページ 14 本で、それより多いと review-2.html・review-3.html … に分かれる（今回分がどのページかは AI が伝える）。AI はイラストに指定外の文字が混じっていないか・サイズが 3:2 かを先に確かめ、気づいた点をチャットに添える。シートの 1 カードは次の 5 つ。

  1. ① 動画（再生できる）
  2. ② スチル 5 枚（先頭 0f・各カット・末尾 479f。先頭と末尾が隣に並ぶので、ループの継ぎ目が自然かを見る）
  3. ③ イラスト（原画）
  4. ④ 問題文とヒント
  5. ⑤ slot_code と content_key（カードの見出しは stock_item_id の番号）

見るところ: イラスト（指定外の文字・数字・記号がないか / 画風がそろっているか / 情景が問題と合っているか）・版面（文字の欠け・重なり・吹き出しとヒント）・音（BGM と効果音のタイミングと音量）・ループの継ぎ目。

ユーザーの返し方: カードの見出しの番号ごとに、直してほしい点をチャットに書く。問題がなければ「全件 OK」。

例:

326 グレーの後の矢印と「?」が「次の色」を問うように見える
329 文字を大きく
336 黒背景に黒いカラスで見えにくい
ほかは OK

返した後: AI がイラストの情景文を直し（ローカル DB と Aurora の両方）、イラストを作り直して、その問題だけビルドし直し、シートを作り直して出し直す。全件が OK になるまで繰り返す（何巡になってもよい）。問題そのものが動画にすると微妙なら、完成稿 NG として候補へ差し戻す。全件 OK になったら、AI が承認した番号を work/approved.txt に書き、G3（配置）のゴールを出す。

判断の記録

本文の「→ 理由 D-xx」から飛んでくる先。

D-01 昼（フェルミ推定）の補充を止める

決めたこと
昼の枠の投稿と補充を当分止め、朝と夜の 1 日 2 回にする（廃止ではない）
理由
昼のスキップ率が高止まりで改善せず、問題にも魅力を感じない。魅力を感じない投稿が定期的に混ざるとフォロワーが増えないため
