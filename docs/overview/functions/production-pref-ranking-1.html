pref-ranking-1 の生産（都道府県ランキング）

現行版 最終更新: 2026-10-18（Phase 30-3c で新設。30-5 で「さらに詳しく」を生産の詳細設計へ向け、3 章 レビューのやり方を追加） 1 段上: 生産ライン（共通）。ここには共通との違いだけを書く

要約

pref-ranking-1 は、都道府県ランキングの TOP5 を地図のルーレットで発表するリールを、毎日 1 本投稿するセットである。生産では、官公庁の統計から順位の元になる数値を機械で読み取り、ナレーション付きの 30 秒の動画を作る。生産ライン（共通）の骨組みのうち、候補を多めに出して選ぶ段階はなく、ネタ選びはリサーチの中で基準に沿って行う。

図 1 はこのセットの工程を表す。共通との違いは、データの読み取りと県への換算が独立した工程としてあることと、関所が素材のレビューと動画の全数レビューの 2 つであること。

項目このセットでは
作るもの都道府県ランキング TOP5 の 30 秒のリール（下位を晒さない TOP5 の版面）
補充スキルranking-stock-replenish（Claude Code）+ 執筆の勘所 WRITING-NOTES.md
在庫テーブルranking_stock_items
関所素材のレビュー・動画の全数レビューの 2 つ（候補の選別はない。やり方は 3 章）
音VOICEVOX のナレーションと BGM

1. 何を作り、素材をどう集めるか

このセットの素材は「順位の根拠になる数値」で、数値は必ず一次情報から機械で取り出す。

項目内容
ネタの出どころ家計調査の品目別ランキングと官公庁の統計が中心（初期のネタ帳は使い切り済み）
ネタの基準下位の県の人が笑って自虐できるか → 理由 D-01
数値の取り方e-Stat や官公庁の xlsx・PDF を抽出スクリプトで読み取る。家計調査は 52 市の値を 47 都道府県へ換算する（common/convert.py）。まとめ記事・ランキングサイトの数値は使わない
素材の置き場content/ranking-stock/pref-ranking-1/<バッチ>/stock_items.py（リサーチの記録は同じ場所の research.md）
機械検証validate.py（同値・読み上げの長さなど）・generate.py

2. 共通との違い

生産ライン（共通）1 章の骨組みと比べたときの、このセットの違い。

  • 候補の選別がない: 候補を多めに出して人が選ぶ段階はなく、ネタの採否はリサーチの中で基準と採否のルールに沿って決め、不採用の理由を記録に残す
  • データの検証が独立した工程: 一次情報の取得・読み取り・県への換算を、執筆の前に機械で行う
  • 投入はビルドより前・配置はまとめて: 素材を全件承認したらローカル DB と Aurora に投入し（両環境の中身の一致を確かめる）、動画を承認したら publish.py が S3・ローカル DB・Aurora をまとめて更新する
  • 背景とナレーション: 背景画像を生成して取り込み、VOICEVOX でナレーションを付けてビルドする
さらに詳しく
  • 手順（工程ごとのコマンド・採否のルール）→ ranking-stock-replenish の SKILL.md
  • 素材と動画の仕様（スロット・音源・ナレーション・デザイン）→ セット別設計書 pref-ranking-1
  • 生産の詳細（資材の置き場・工程ごとの規定・事前ビルド・在庫の数え方）→ 生産の詳細設計 pref-ranking-1
  • 投稿時に在庫から 1 件を選ぶ規則 → 方式設計書 ranking-prebuilt 4 節
  • 運用の値（補充の目安・在庫水位・直近の補充）→ セット計画書 pref-ranking-1

3. レビューのやり方（2 つの関所）

このセットの人の関所は 2 つで、どちらもページ（ブラウザー）で中身を見て、結果をチャットで返す。候補の選別はない。表 1 は、2 つの関所がいつ来て、どこで何を見て、どう返すかを表す。関所の考え方は生産ライン（共通）5 章。

表 1 pref-ranking-1 の 2 つの関所
関所いつ場所見るもの返し方
① 素材のレビュー執筆と機械検証の後・投入の前素材のレビューページ <バッチ>/review.html（バッチの一覧から今回のバッチを開く）+ チャットネタごとの TOP5・出典・表示文言・ナレーション。AI の一次スクリーニングの結果ネタ番号ごとに指摘、または「全件 OK」。全件承認まで投入しない
② 動画の全数レビュービルドの後・配置の前レビューシート work/review.html + チャットネタごとの動画（30 秒版）・背景・版面の文言・TOP5・cue 台本・BGM・ラウドネスcontent_key ごとに指摘、または「全件 OK」。承認はネタ単位

3.1 ① 素材のレビュー（レビューページ + チャット）

数値・出典・文言が正しいかを、投入の前に確かめる関所。誤ったデータを止める唯一の関所。

AI が出すもの:

  • 素材のレビューページ content/ranking-stock/pref-ranking-1/<バッチ>/review.html（generate.py が作る。バッチごとに場所が変わるので、バッチの一覧から今回のバッチのフォルダーを開く。AI もチャットに今回のパスを書く）。冒頭にレビューの観点と「表示文言のフィールドがどこに出るか」の表と目次があり、その下にネタごとの TOP5（順位・都道府県・値）・出典・表示文言・ナレーション（cue 台本）が並ぶ。ブラウザーか VS Code の Live Preview で開く。AI がページを書き直したら再読み込みする（「直っていない」の多くは古い表示のまま）
  • チャットに一次スクリーニングの結果: blocker の候補と申し送りを先に書く。見る点は、単位・前提が画面に出るか / 同じ出典・近いテーマが並んでいないか（投稿日を離す材料）/ 3 位と 4 位のような僅差で順位が確かか / 誇張が数字を超えていないか / 下位に触れていないか / 吹き出しで熟語の途中で改行しないか

例:

【第 N バッチ 素材レビュー 7 件】review.html を開いてください
blocker 候補: 033 の hook「…」は 12.2% を「8 人に 1 人」と丸めていて数字を超えています。代案: …
申し送り: 031 と 035 は同じ出典（rank13 外食）なので投稿日を離してください / 034 は 3 位と 4 位が 2 円差です

ユーザーの返し方: ページを見て、ネタ番号ごとに直してほしい点をチャットに書く。AI の代案を選ぶだけでもよい。問題がなければ「全件 OK」。見る観点は、データの正しさ（出典・データ年・県換算・TOP5 の順位）・表現（下位を晒していないか・煽りすぎていないか・出典表記と注記）・既存との重複・書式（文字数・cue 台本の長さ・bg_motif）の 4 つ。

返した後: AI が単一ソース（stock_items.py。数値は data/*.json）に反映し、validate.py → generate.py を回し直してページを作り直し、もう一度出す。全件を承認するまで投入しない。

3.2 ② 動画の全数レビュー（レビューシート + チャット）

ビルドした動画を全部見て、S3 に置くものを決める関所。

AI が出すもの:

  • レビューシート content/video-build/pref-ranking-1/work/review.html（review_sheet.py が作る）。ネタごとに 1 枠で、動画（30 秒版）・背景・版面の文言・TOP5（値と版面での表示）・cue 台本・BGM・実測のラウドネスが並ぶ
  • チャットに一次スクリーニングの結果: AI は出す前に、ビルドした動画から 14 秒（3 位）・22 秒（1 位の発表）・27 秒（結果総覧）のスチルを切り出して見る。背景は素材単体では良くても、合成すると地図を横切って読みにくくなることがあるので、合成後の画で確かめる

見るところ: 背景（文字・数字・記号が混じっていないか / 和モダンの画風か / 版面の読みやすさを邪魔しないか）・版面（県名と数値が正しいか / 金が沈んだりにじんだりしていないか / 文字の欠け・見切れ / 地図の点灯と順位の行が合っているか）・音（県名が停止のフラッシュに合うか・語尾が切れていないか・BGM とのバランス）。

ユーザーの返し方: content_key ごとに直してほしい点をチャットに書く。問題がなければ「全件 OK」。

例:

030-xxx 本棚の柱が地図を横切って読みにくい
027-xxx 1 位の県名の読みが停止より遅れて聞こえる
ほかは OK

返した後: AI が背景を作り直すか（構図まで指定して頼む）、bg_motif・セリフ・文言を DB で直してビルドし直し、シートを作り直して出し直す。直るまで承認しない。承認はネタ単位で、全件 OK になったら AI が承認した content_key を work/approved.txt（承認の台帳）に足し、そのバッチ分だけのファイルを作って配置に進む。
