umigame-soup-1 の生産（ウミガメのスープ）

現行版 最終更新: 2026-10-18（Phase 30-3c で新設。30-6a で「さらに詳しく」を生産の詳細設計へ向けた） 1 段上: 生産ライン（共通）。ここには共通との違いだけを書く

要約

umigame-soup-1 は、探偵カメロックが出すウミガメのスープ（不思議な状況から真相を推理する問題）のリールを週 4 回投稿し、視聴者のコメントにコメント自動返信が答える参加型のセットである。生産では、問題をオリジナルで作問し、動画の素材に加えて、コメントを判定するための材料（判定の基準・核心語）まで作る。そのため、ほかのセットにはない「判定の試行（プローブ）」の工程と関所がある。

図 1 はこのセットの工程を、補充スキルのゴール（G1a〜G5）の単位で表す。共通との違いは、判定の試行が入ることと、動画のビルドを DB への投入より前に行い、投入と配置を最後にまとめて行うこと。

項目このセットでは
作るものウミガメのスープの問題 1 問 1 本のリール。物語復元型と意味誤誘導型の 2 つの型を同数ずつ作る
補充スキルumigame-stock-replenish（運用）+ umigame-problem-writer（作問）。どちらも Claude Code
在庫テーブルumigame_stock_items（動画の素材に加え、真相・判定の基準・核心語を持つ）
関所候補の選別・素材のレビュー・コメントのレビュー・判定の試行の GO・動画の全数レビューの 5 つ
音Irodori-TTS（ローカル）のナレーションと BGM

1. 何を作り、素材をどう集めるか

このセットの問題はすべてオリジナルで、作問スキルが決まった工程で作る。既存の問題と似すぎていないかも作問の中で確かめる。

項目内容
作り方型を宣言 → ランダムに引いた語（モチーフ）から連想 → 型ごとの工程でコア（真相の核）を宣言（物語復元型は、先に完結した物語を書いて面白さの関門を通し、どこを隠すかを決める。意味誤誘導型は、言い方を変えて誤解を生む）→ 不思議にする → 動線・現実性・既存問題との照合で自己検査 → 素材化
型物語復元型（story）と意味誤誘導型（misdirection）。1 バッチの中で同数
候補の置き場content/umigame-stock/umigame-soup-1/candidates/<バッチ>/（第 2 バッチで新設する）
素材の置き場content/umigame-stock/umigame-soup-1/batch-NN/stock_items.py
機械検証と試行validate.py・generate.py、判定の試行は probe_run.py（本番と同じ判定と返信文の経路）・build_probe_page.py・local_trial.py（人のプローブ）

2. 共通との違い

生産ライン（共通）1 章の骨組みと比べたときの、このセットの違い。

  • 判定の試行（プローブ）: 動画を作る前に、問題ごとに試行用のコメントと期待する判定を用意し（人がレビュー）、本番と同じ判定に通して結果を人が確かめる。食い違いは素材の穴かラベルの誤りかを切り分けて直し、GO が出た問題だけを動画へ進める → 理由 D-01
  • ビルドが投入より前: 動画のビルドは stock_items.py を読むので DB への投入を待たない。投入（ローカル DB と Aurora）と配置（S3）は最後の G5 で一括して行う
  • 作問を別のスキルに分ける: 作問は umigame-problem-writer が受け持ち、G1a で候補（コア宣言）までをまとめて、G1b で OK になった案を 1 問ずつ素材にする
  • 背景とナレーション: 背景画像を生成して全数を目視で確かめ、Irodori-TTS でナレーションを付けてビルドする

判断の記録

本文の「→ 理由 D-xx」から飛んでくる先。

D-01 動画を作る前に判定の試行を通す

決めたこと
問題ごとに試行用のコメントで本番と同じ判定を走らせ、人が GO を出した問題だけを動画にする
理由
投稿後のコメントには自動で返信するため、素材（真相・判定の基準・核心語）に穴があると誤った返信が出る。動画にする前に見つければ、素材の手直しだけで済む
