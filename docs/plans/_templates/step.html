テンプレート 最終更新: 2026-09-21（Phase 25-1 で新設）。このページは計画ではなく見本で、ここに書かれたフェーズ・ステップ・日付はすべて架空。実際の計画は開発計画と各セット計画書にある。
使い方 下のコピー範囲（<!-- ここから --> 〜 <!-- ここまで -->）を計画書に貼り、ID・状態・本文を書き換える。様式の原則（4 項目の意味・人間ゲートの置き方・記録の移管時期）は 計画体系が正で、ここでは繰り返さない。構造の契約（属性名・必須欄・例外形式）の正は変更ファイル・展開草案セクション 2、機械検査は tools/docs_plan_check.py。

結果：常時表示に残す要点を 1〜2 行で。詳細は作業記録と開発記録へ。

1. 何をするか

成果物を短く説明する。長い仕様は下の「実装の細部・背景」へ入れ、ここでは何が出来上がるかだけを書く。

守る条件

壊してはいけないもの・触らない範囲を書く。無ければ「なし」と明記する（空欄にしない）。

2. 完了条件

  1. 条件は 1 つずつ箇条書きにする（ul / ol のどちらでもよい）。
  2. 機械で確かめられる形にし、貼る出力（テスト要約行・件数クエリ等）を指定する。
  3. 計画・記録の更新、日本語メッセージでのコミット、pull --rebase、push まで含める。

3. 人が確認すること・止まる場所

人が確認すること

このステップではなし。次のステップで実機確認を行う、のように誰がいつ何を見るかを書く。

止まる場所・上限

push まで（触るディレクトリを書く）。stop after 20 turns。やらないことも明記する。

4. 実装の細部・背景 — 見出しに中身の要点を添える

定数・ファイル構成・設計判断の理由など、着手時に必要だが常時表示すると読み取りを妨げる情報。

5. 作業記録 — 完了・検証まで一巡

作業中はここに追記する。方針が変わったら常時表示の「何をするか」「完了条件」も直す（記録だけに残さない）。

3. 属性の早見表

見出しの日本語では機械判定せず、属性で構造を示す。本文の正は各計画書で、属性は検査と表示のためにある。検査仕様の全文は展開草案セクション 2。

対象書き方検査で NG になる例
ページ<body data-plan-format="1">。検査対象は docs_plan_check.py の REGISTERED_PAGES で管理する。ステップを 1 件も持たないページ（停止セットの計画書など）は data-plan-steps="none" を併記して明示する（25-5 で追加）登録済みページから属性を消す / 宣言のないページでステップ 0 件 / data-plan-steps="none" のページにステップがある / none 以外の値 / 旧形式の行が混ざる
フェーズsection.plan-phase[data-plan-phase]。中に完了済みグループ（details[data-plan-group="done"]・open を付けない）と進行中グループ（[data-plan-group="active"]）を置き、完了済みが先完了済みが進行中より後 / 完了済みグループに open
ステップarticle.plan-step + id="step-<ID>" + data-step-id + data-status="todo|doing|done|blocked"。done は data-completed="YYYY-MM-DD" が必須ID 重複 / done が進行中グループにある / 完了日なし
常時表示の欄data-field="overview|prerequisites|constraints|acceptance|gate|stop|result"。空欄不可（該当なしは明記）。acceptance は ul / ol必須欄の削除 / 空欄 / 完了条件が折りたたみの中
折りたたみdetails[data-field="implementation"] と details[data-field="record"] を別々に置き、open を付けない。整理後の記録は section[data-field="record"] + リンクでも可初期展開（open）/ 実装詳細と記録の同居
例外形式ユーザー判断は data-kind="decision"（「ゴール対象外」と「ゴールにしない」を表示）。古い完了ステップは data-kind="legacy-completed"（記録リンクで代替）done 以外で legacy-completed を使う / 判断ステップに停止点の明記がない
検査が担保しないこと 重要な制約が文章としてすべて拾われているか・要約が正しいか・記録と最新状態が一致するか、の 3 点は機械では見ない。更新者は差分のステップについてこの 3 点を読み直す。構造検査の成功を内容の正しさと同一視しない。
