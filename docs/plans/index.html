3. 並行作業ルール

  • セッション起動時にレーンを宣言する: 「開発レーン: 16-5」「セットレーン: pref-ranking-1 の週次補充」のように、レーンと触るパスを冒頭で確認してから着手する。補充スキル（/quiz-stock-replenish / /ranking-stock-replenish）の起動はセットレーン宣言を兼ねる
  • 計画書のステップ着手は /step <識別子> から（両レーン共通・Phase 19-2 で導入）: 起動がレーン宣言と /goal 完了条件の宣言を兼ねる。手順・テンプレの正は .claude/skills/step/SKILL.md
  • git は trunk（main）直 push を継続し、push 前に git pull --rebase origin main を必ず挟む。書き込みファイルがレーンで分離されているため、競合は原則発生しない
  • 開発レーンは常に 1 本: services/ / shared/ に触れる push は CodePipeline 完走 + タスク定義新リビジョン確認まで見届ける必要があり、並行すると確認が混線するため
  • レーンをまたぐ気づき（セット作業中に見つけた基盤の課題等）は、自分で直さず相手レーンの計画書に課題として記録する（セット → 開発: 設計課題リストへ / 開発 → セット: セット計画書のバックログへ）
  • 本ディレクトリの整理・ルール変更（Phase 18 級の作業）は、他セッションが 1 本も動いていないフリーズ窓で単独実施する

4. 記録の分担

  • plan（毎セッション読む）: ステータス / バックログ / 進行中ステップ。完了したらチェック + 完了日 + 要点 1〜2 行だけ残す
  • log(必要なときだけ読む): 実施の詳細全文。週次補充は「1 回 = 表 1 行(日付・投入件数・在庫水位・特記)」の定型とし、特記事項があるときだけ本文を書く
  • トラブルの二分: セット固有の事象の記録はセット log へ、恒久対策の課題（コード・共通設計書に触れるもの）は開発レーンの設計課題リストへ（相互リンクを張る）
  • 同じ情報を複数ドキュメントに書かない原則は従来どおり。詳細は 1 箇所に書き、他からは参照リンクを張る
