2. 問題ストックの作り方

この章は、図 1 の上半分（候補からプローブの GO まで）を詳しくしたもの。作問の工程（ランダム語のモチーフ → 連想 → コア宣言 → 不思議にする → 動線・現実性・既存問題との照合の自己検査 → 素材化）は umigame-problem-writer が正。

2.1 オリジナル性の基準

  • 既存の問題の問題文・真相を転載しない。語句・登場人物・舞台の置き換えだけの改変もしない → 理由 D-05
  • 借りてよいのは型（物語復元 / 意味誤誘導）と仕掛けの構造まで。モチーフ・真相・問題文は新しく作る。台帳で本家級（classic）の題材は構造ごと避ける。PoC の古典題材だけは例外で、ストックには入れない
  • 作問法の正は note 記事の 4 ステップ + 良い問題の 3 条件
  • source_note に「完全オリジナル」の宣言・型・モチーフ → 連想 → 逆にした常識を書く（validate.py が宣言を検査する）

2.2 候補と選別

  • 型別の目標（週 4 問なら物語復元 2 / 意味誤誘導 2）の 2 倍の候補を書く。前のバッチの余った OK を先に数える
  • 候補は 1 案 3 行（コア宣言 1 文・問題文の案・何を言われたら「正解です！」か）。既存の全バッチの問題・台帳との照合（Web での類題の照合を含む）は候補の段階で済ませる。素材の項目は書かない
  • 選別は OK / NG / 保留だけで、理由は任意。不足 = 目標 − OK、追加 = 不足 × 2 で、両方の型とも不足が 0 になるまで素材に進まない。NG・保留は消さない

2.3 素材の仕上げと素材のまとめレビュー

  • OK のうち目標数だけを 1 問ずつ素材にする（作問スキルの工程 4〜9）。余った OK は次回へ持ち越す。管理項目 core（コア宣言の 1 文。DB には入れない）は validate.py が様式を検査し、素材シートは問題文の直前に出す（レビューはコア宣言から見る）
  • 機械検証は validate.py（字数・必須項目・#AIart・画風の固定行・プレイ例の「はい」1 つ・オリジナル宣言など）。素材シートは review_sheet.py（API キー不要。<バッチ>/work/review.html）で、書くたびにセット直下の素材シートのインデックス work/review.html（全バッチの一覧。tools/review_index.py）も更新する
  • 素材のまとめレビューでは、人が素材シートで矛盾・ネタバレを一括で見る。素材で NG になった問題は候補へ差し戻す（final_ng）

2.4 本番経路のプローブ

  • 作問時に、本番と同じ判定・返信文の経路で答えを確かめる: 問題ごとにプローブ用のコメントと正解ラベル（期待する判定の種類）を作り、コメントのレビュー（正解ラベルも人が確かめ、追加・削除・ラベルの修正を指示する）の後で評価データ judge-trial/data/eval_problems.json に足して、tools/probe_run.py --problems <no> を回す → 理由 D-06
  • 結果は build_probe_page.py がバッチのプローブページにする。不一致は「確定事実シートの穴 / 正解ラベルの誤り / 判定の揺れ」に分けて出す。必要なら人が local_trial.py で自由にコメントを試す（人間プローブ）。GO が出た問題だけを動画のビルドへ進める
  • 評価データ・機械プローブ・評価ページの仕組みはセット別設計書 10.6
さらに詳しく

  • ゴールの切り方・在庫確認のクエリ・投入のコマンド → umigame-stock-replenish の SKILL.md

3.2 背景イラスト

1 問 1 枚の背景を、ストックの illustration_prompt から Codex CLI の image_gen.imagegen（codex exec）で作る（生成方式 umigame-prebuilt は実行時に LLM・画像生成 API を呼ばない）。プロンプトは「画風の固定行 + 情景 + 禁止事項」の 3 部で、画風の固定行は全問共通の定数（validate.py が存在を検査する）。

  • 画風（C4）: 90 年代 OVA の手描きセル塗り（太い主線・エアブラシのハイライト・リムライト）。背景は中間調（月明かりと蝋燭で情景が見える明るさ）で、版面のオーバーレイは薄くする → 理由 D-07
  • 禁止事項: 文字・ロゴを入れない。真相の手がかりを描かない（問題文にある情景だけ。人物は問題文に出る人物 + 遠景のシルエット 1 人まで）
  • 人物の大きさと位置: 遠景の小さな全身像で、下半分の中央（横幅の中央 20%・縦 55〜85%）にだけ置く。上半分は人物なしで静か（空・壁・天井・窓）、下半分の左右 40% は景物だけ。クローズアップ・半身は描かない（感情は姿勢で出す）。理由はセット別設計書の付録
  • 9:16 を指定して生成し（出力は 1024x1536）、intake.py（prepare_assets.py）が 1080x1920 へ正規化する
  • 背景のレビューは background_sheet.py（背景を投稿順に並べた work/backgrounds.html）と background_sheet.py --stills（今の文言と背景で動画の各コマを書き出す）で、版面と重ねて見る。Claude が先に全数を見る（文字の混入・構図）
  • キャラクター 2 体はストックごとには作らない

  • ナレーションの予算（21 秒）を使い切っても尺の内側で終わる。導入の読み上げは問題文の読み上げ（165）の 6 フレーム前までに終わる（build.py が検査する）
  • 吹き出しの切り替えはスナップ（クロスフェードしない）。切り替えのフレームで SE を 1 回鳴らし、小さな跳ね（30px・減衰 0.8 秒）を付ける。跳ねは導入シーンの自己紹介の吹き出しでも起きる（HOP_FRAMES）
  • 周期のある動きの周期は 24 秒版の値のまま（光沢 120 / 呼吸 144 など）。一本道なので「尺の約数」の制約はない
  • 実装は Interactive.Div + inline style + inline interpolate() の構造を保つ（Remotion Studio で要素を選んで調整できる）。周期のある動き（sin のゆれ）は interpolate() で書けないので translate の文字列で書く → 理由 D-03

  • 長さの制御と取り直し: 話速の調整（atempo）はせず、--seconds 20.0 で合成する。2 cue + 間の合計が 21 秒を超えたら、seed を 1 つ進めて --seconds を 0.5 秒縮めて取り直す（1 回のビルドで最大 3 テイク = 20.0 / 19.5 / 19.0 秒）。聞いて気になった問は build.py --retake-tts --content-key <key> で seed を進めて取り直す（1 問 3 回まで）
  • work/narration/<key>/narration.json にモデル・参照音声（名前と sha256）・精度・seed・長さ・切断位置・試したテイク・通算の合成回数（attempt）を残し、文・モデル・参照音声・精度・長さの設定が一致して予算内ならキャッシュを使う
  • 導入の読み上げは全問共通の 1 文: narration_irodori.synthesize_line で 1 回だけ合成して work/narration/_opening/ にキャッシュし、全問で使い回す（--no-tts ではそれを読む）。文・長さの設定が変わったら取り直す
  • 予算の超過はビルドエラー（3 テイクとも超えたら問題文か cue の句読点を削る）。infer.py の失敗（GPU・環境）はその場でビルドを止める
  • BGM と音: BGM は @remotion/media の <Audio> で尺ちょうど（29 秒。prepare_bgm.py が common.DURATION_SECONDS で切り出してフェードを焼き込む）のトラックを敷く。導入と本編のナレーションの区間は BGM を -6dB 程度ダッキングし、SE は切り替えのフレームに置く。最終の MP4 を -14 LUFS / -2 dBTP へ正規化する
  • TTS のアダプタ: Irodori が既定（ビルド時にローカル GPU で動かし、API キー・AWS の Secret は要らない）。Gemini 版（日次の上限のため本番では使わない）・Polly 版（Takumi 125%。21-5a・21-5b の初版 14 本で使った）は build.py --tts で選べる形で残してある。VOICEVOX 版（scripts/narration.py）は PoC 用の CLI として残してあり、build.py からは選べない。声と設定の正はセットの資産 assets/design.json と参照音声 assets/voice/kamerock-g4/（セット別設計書 8 節）

  • 版面（timeline.ts / UmigameReel.tsx）・キャラ画像・フォント・SE・尺

  • Remotion / @remotion/media の版（見た目が変わりうる）

D-01 ビルドの読み元は DB ではなくバッチの stock_items.py にする

決めたこと

D-02 導入シーンを足し、ループをやめて一本道の 29 秒にする

決めたこと

理由
